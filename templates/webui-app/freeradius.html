Server

Switches and access points send RADIUS to {{ r.host_ip }} UDP 1812 (accounting 1813). Supplicants check the server certificate {{ r.server_name }}, issued by the fabric CA.

Devices: decided per device on 802.1X → Devices: a role with network:eap-tls (certificate linked to the device) or network:mab (the device's MAC), and optionally a VLAN. A disabled device, or an unlinked certificate, is refused at its next authentication. People and domain machines: by password (EAP-TTLS or PEAP, checked by the domain), only members of the groups below (for machines, e.g. Domain Computers).

{% elif view == 'switches' %}

Any switch or access point

Give the switch these RADIUS settings (the names differ by vendor):

RADIUS server
{{ g.host_ip }}
Authentication port
1812 (UDP)
Accounting port
1813 (optional; acknowledged, not stored)
Shared secret
the one shown when you added the switch on RADIUS clients (lost it? New secret)
Dynamic VLAN
turn on "RADIUS-assigned VLAN" (fabric sends Tunnel-Private-Group-Id)

Per port, choose how the device on it proves who it is:

  • 802.1X — laptops, desktops, phones: a certificate (EAP-TLS, device roles on 802.1X → Device roles) or a password checked by the domain (EAP-TTLS or PEAP, mapped groups).
  • MAC authentication (MAB) — printers, cameras, IoT without 802.1X: the device's MAC must belong to a device whose role grants network:mab.
  • Always open — uplinks, access points, the port this fabric host is on, and the port of the switch's own controller. Closing those locks the network (and you) out.

Every VLAN a device role or mapped group names must exist on the switch with the same number.

UniFi (UniFi Network application)

Untested with fabric yet: labels can differ between UniFi Network versions.

  1. In fabric: RADIUS clients → add the switch by its management IP (UniFi → Devices → the switch → its IP). Keep the shared secret.
  2. UniFi → Settings → Profiles → RADIUS → Create New: name fabric; Authentication server {{ g.host_ip }}, port 1812, the shared secret; Accounting server (optional) {{ g.host_ip }}, port 1813, the same secret; turn on Wired networks and RADIUS assigned VLAN (wired).
  3. UniFi → Settings → Networks: create the VLANs fabric's roles and groups use, same numbers.
  4. UniFi → Devices → the switch → Settings → Services → 802.1X Control: on, RADIUS profile fabric. Fallback VLAN: leave empty (refused devices get no network) or a guest VLAN.
  5. UniFi → the switch → Ports: per port, 802.1X Control — Auto for 802.1X devices, MAC-based for printers and IoT, Force Authorized for uplinks, access points, the fabric host and the UniFi console.
  6. Check: plug a device in; Recent decisions shows accepted / refused and why.

MAB devices never show up in Recent decisions? The switch may not send a Message-Authenticator, and fabric drops such requests (BlastRADIUS protection). Remove the switch and add it again with "Require Message-Authenticator" off, only for that switch.

{% elif view == 'windows' %}

Windows: this PC joins with its certificate (EAP-TLS)

For fabric's own PCs: the port opens with the computer's certificate, before anyone signs in.

  1. Directory → Devices → Add: the PC by name, in the workstations role (or any role with network:eap-tls).
  2. Step-CA → New key + certificate: CN = the PC's name, for that device (it is linked automatically). Download the .p12 and keep its password.
  3. Copy the .p12 and this script to the PC: {{ g.windows.tls.filename }}
  4. In PowerShell as Administrator: 
    powershell -ExecutionPolicy Bypass -File .\{{ g.windows.tls.filename }} -Pfx .\<pc>.p12
  5. Plug the PC into an 802.1X port. Recent decisions shows ACCEPT eap-tls and its VLAN.

Windows in the domain: nothing to do (PEAP)

A PC joined to the domain gets the 802.1X profile from its site's Windows baseline policy: Wired AutoConfig on, PEAP to {{ r.server_name }} checked against the fabric CA — first as the machine (map Domain Computers or a group of machines), then as the person signed in. See the manual, 4.6.7.

Windows outside the domain: people sign in with their user name and password (EAP-TTLS)

For PCs anyone may use: whoever sits down signs in to the network with their directory account. Only members of {% if g.people %}{% for grp in g.people %}{{ grp }}{{ ', ' if not loop.last }}{% endfor %}{% else %}a mapped group (none yet){% endif %} get in.

  1. Put the person in a mapped group (Keycloak → Groups, e.g. network-staff).
  2. Run this script on the PC, in PowerShell as Administrator: {{ g.windows.ttls.filename }} 
    powershell -ExecutionPolicy Bypass -File .\{{ g.windows.ttls.filename }}
  3. Plug the PC into an 802.1X port: Windows asks for the user name and password.

Five wrong passwords lock the account for 15 minutes (the directory's lockout). There is no second factor for network logins.

What the scripts do

  • Turn on Wired AutoConfig (dot3svc), the Windows service for wired 802.1X — off by default.
  • Trust the fabric root CA and pin the server: Windows only talks to {{ g.server_name }} with a certificate from this CA, without asking the user (a fake access point cannot collect passwords).
  • Import the PC's certificate into the computer's store (EAP-TLS), and add the 802.1X profile to the wired adapter (-Interface, default Ethernet).

Made for this network (public data only: the root CA and names). Untested on Windows by the fabric project until the hardware test. Not working? netsh lan show interfaces on the PC, and Recent decisions here.
