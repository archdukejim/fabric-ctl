## 1.8.3.1 Web UI as the single pane

Same security model (mTLS + Keycloak OIDC + TOTP + CSRF) and the same
privilege split: the UI runs in its own unprivileged container (`webui`, no
caps, read-only, no Docker socket) and reaches the host only through
`fabric-agent` — a root host service with a fixed, validated, audited JSON
API on a unix socket (SO_PEERCRED-checked). Each new section is a new agent
endpoint over `fabricctl` actions, so CLI and UI never diverge:

- **DHCP:** subnets, live leases (lease API), reservations (creates DNS).
- **802.1X:** RADIUS clients, recent auth log, device certs (issue/revoke),
  VLAN mappings, CoA.
- **PKI:** issued certs, expiry, revoke, SCEP/ACME provisioners.
- **Directory:** users/groups in the domain (Samba AD, [1.6.3](1.6.3-samba-directory.md); through the
  least-privilege `fabric-agent-<site>` account, not the Administrator).
- **Health:** `fabricctl doctor` output, service status, versions, updates.

Role split (Keycloak realm roles): `fabric-console-admin` (everything),
`fabric-operator` (DNS/DHCP/leases, no PKI/directory), `fabric-auditor`
(read-only). *Superseded by the RBAC bundles of [1.6.8.1](1.6.8-rbac.md#1681-access-control-for-people-rbac-across-the-stack-decided-2161-built) (2.1.6.1).*

> **Built:** tabs Overview (service health), BIND9 (forward and reverse
> zones, records, TSIG keys), Kea (subnets, reservations with apply, live
> leases), Step-CA (CA, sign a CSR, new key + certificate, inspect, convert,
> issued list), Directory (devices, device roles, certificate links, people:
> add a person, reset a sign-in), FreeRADIUS (RADIUS clients, group
> mappings, recent decisions, setup guides) and OpenBao (status, unlock
> methods, secrets pointer, disk-encryption guide). The web UI app lives in
> `src/webui/` and the agent in `src/agent/`. **Not yet:** certificate
> revocation, SCEP/ACME provisioners, CoA, DHCP names under the BIND tab,
> `fabricctl doctor` output and image updates in the UI; the version is
> shown only in the footer.

## 1.8.3.2 The console's frame: a navigation down the left, as Cockpit has it

**Designed 2026-10-11 for 0.9 (decisions 2.1.8.5, 2.1.8.6), not built.** The owner, reviewing `v0.8.0-rc.2`: "I really
like the cockpit layout, could mirror that layout instead?"

- **The frame.** A bar across the top: the install's name and host, the version, and the person signed in (their
  menu: sign out). Down the left, the navigation, one entry per part, its pages below it when it has several; the
  page fills the rest. On a narrow screen the navigation folds into a button. The tab row across the top goes.
- **The entries:** Overview; DNS (its pages: Zones (BIND9), DNS filter); DHCP; PKI; Directory; 802.1X; Secrets
  (OpenBao); Federation; Security. A part that is not installed shows its page with how to turn it on (as today),
  without a badge.
- **Permissions decide what shows**, as today: an entry appears for anyone who may see one of its pages; each page
  checks its own permission (DNS: Zones `dns:read`, writes `dns:write`; DNS filter `dns:filter`).
- **Kept:** the pages' contents, their routes and forms (the paths stay, so links and tests hold), the strict
  Content-Security-Policy (no inline script or style: the navigation's folding is CSS only), the colours and type.
- **Tests:** the devserver's page checks see the navigation and that a person sees only the entries their permissions
  allow; a narrow-screen check; the webui container suite unchanged in behaviour.
