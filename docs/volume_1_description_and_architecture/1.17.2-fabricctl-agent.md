### 1.17.2.2.5 `Handler.authorize(self, method, route)`

| | |
|---|---|
| Purpose | decide whether this request may run: root peers always; everyone else needs a valid Keycloak ID token that grants the permission the route requires. |
| Inputs | method — "GET" or "POST"; route — list of path segments after /v1/. Reads the "Authorization: Bearer <token>" header and vars (load_vars) for token verification. |
| Returns | None when allowed, with self.user = the token's preferred_username, self.perms = its permission set and self.session = its `sid` (all None for a root peer); otherwise (status, error): (401, reason) when verify_user_token rejects the token or it is missing; (403, "not allowed") when required_permission lists no permission for the route (default deny); (403, "you need the permission <p>") when the token lacks it ("session" needs none). |
| Fails | exceptions other than ValidationError (e.g. KeyError on a token without preferred_username, OSError from load_vars) propagate to dispatch, which answers 500. |
| Feeds | dispatch; self.user feeds actor (and the caller fabric-agent's checks name), self.perms the routes that need a second permission, self.session a person's own password change. |
| Called by | `agent.handler.Handler.dispatch` |

| | |
|---|---|
