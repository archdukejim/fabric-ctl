## 1.2.1.2 System Topology

```mermaid
graph TB
    subgraph LAN["LAN (lan_cidr)"]
        CLIENT[Client devices]
        HOST[Pi / bare-metal host]
    end

    subgraph FABRIC["Docker bridge — fabric_net (10.255.0.0/24)"]
        NGINX["nginx :10.255.0.10\nports 80 · 443"]
        BIND9["bind9 :10.255.0.30\nhost port bind_dns_port → :53"]
        STEPCA["step-ca :10.255.0.40"]
        KC["keycloak :10.255.0.60"]
        PG["postgres :10.255.0.70"]
        WEB["fabric-web :10.255.0.80\nunprivileged, no ports"]
        BAO["openbao :10.255.0.90\nstatic seal · raft"]
    end

    AGENT["fabric-agent (host systemd, root)\nunix socket only"]
    DC["samba (AD DC), host network\nsee 1.2.1.5"]

    CLIENT -->|"DNS · HTTPS"| HOST
    CLIENT -->|"Kerberos · LDAP · SMB"| DC
    HOST -->|"DNS :53 (published by Docker)"| BIND9
    HOST --> NGINX
    NGINX -->|"DoH /dns-query → :8053 (the DNS filter's resolver when on, 1.12.2.16)"| BIND9
    NGINX -->|"fabric-ctl.<domain> (mTLS) → unix socket"| WEB
    NGINX -->|"sso.<domain> → :8443"| KC
    WEB -->|"OIDC · admin REST"| KC
    WEB -->|"unix socket · fixed JSON API"| AGENT
    KC -->|"LDAPS 636 at host_ip"| DC
    AGENT -->|"LDAPS"| DC
    KC --> PG
    NGINX -->|"ca.<domain> → :9000"| STEPCA
    NGINX -->|"vault.<domain> → :8200 (TLS verified)"| BAO
    AGENT -->|"AppRole · status"| BAO
    BIND9 -.->|"internal DNS"| STEPCA
```

Optional services: `kea-dhcp4` (host network, DHCP on the LAN) with `kea-ddns` (10.255.0.97, dynamic updates into BIND9), `freeradius` (10.255.0.98, UDP 1812/1813 on `host_ip`, asks the DC over LDAPS and winbind) and `fluentbit` (10.255.0.95, reads the host journal and OpenBao's audit log).

## 1.2.1.4 Request flow — TLS certificate issuance

```mermaid
sequenceDiagram
    participant F as fabricctl (setup / certs)
    participant S as step-ca
    participant N as service (nginx, bind9, samba, keycloak, postgres)
    F->>F: missing, expiring < 30 days, or a name missing?
    F->>S: step ca certificate (RSA 4096, via the running CA)
    S-->>F: signed leaf + intermediate
    F->>N: install (service uid, key 0600) → restart only that service
```

## 1.2.1.5 Topology with Samba AD

The design of [1.6.3](1.6.3-samba-directory.md) and [1.6.5](1.6.5-samba-dc.md),
approved by the owner 2026-10-04 and built in steps S1–S7 (2026-10-05). The DC side of 1.2.1.2 in detail: the DC
runs in the host network on the LAN interface (2.1.6.18); nginx passes no LDAP through; 389-DS (`dirsrv`) went in S7.

```mermaid
graph TB
    CLIENT[Clients: Windows, Linux, phones]
    subgraph HOSTNET["host network (LAN interface)"]
        DC["samba (AD DC)\n88 · 135 · 389 · 445 · 464 · 636 · 3268/9 · RPC 49152-49251"]
        CHRONY["chrony (host)\nsigned NTP through the DC's socket"]
    end
    subgraph FABRIC["fabric_net"]
        NGINX["nginx\n80 · 443"]
        BIND9["bind9\n53 · fabric's zones + AD zone (DLZ)"]
        KC["keycloak"]
        RADIUS["freeradius\n1812/1813"]
        WEB["fabric-web"]
    end
    AGENT["fabric-agent (host, root)"]
    CLIENT -->|"Kerberos · LDAP · SMB · RPC"| DC
    CLIENT -->|"DNS"| BIND9
    CLIENT -->|"NTP"| CHRONY
    CLIENT -->|"HTTPS"| NGINX
    BIND9 -.->|"DLZ: DC's database (read-only mount)"| DC
    KC -->|"LDAPS 636 at the host's address"| DC
    RADIUS -.->|"ntlm_auth: winbind socket (mount)"| DC
    RADIUS -->|"LDAPS: devices"| DC
    WEB --> AGENT
    AGENT -->|"LDAPS: fabric-agent-<site>"| DC
    CHRONY -.->|"ntp_signd socket"| DC
```
