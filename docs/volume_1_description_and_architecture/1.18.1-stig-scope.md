## 1.18.1.1 Status

**Designed 2026-10-22, nothing built** (decisions 2.1.1.66, 2.1.1.67, 2.1.18; research 2.3.18). This chapter is the home
of STIG compliance (5.8): which of DISA's Security Technical Implementation Guides (STIGs) and Security Requirements
Guides (SRGs) apply to fabric, part by part, what is exempt, and when. How compliance is recorded and proven is
[1.18.2](1.18.2-stig-checklist.md); the STIG baselines fabric offers the domain's members by Group Policy are
[1.18.3](1.18.3-stig-gpo-baselines.md). The release that closes it is 0.11.0 (1.1.4.6). Security defaults that hold
today stay in 1.2.8; they are the floor the STIG work builds on.

## 1.18.1.2 The owner's request

The owner, 2026-10-22 (2.1.1.67): apply "the AS&D , API, CA, DNS and Application Server STIGs as applicable to all the
items we have", "as secure as possible", except that fabric's users are not the DoD (now styled the Department of War,
DoW, in DISA's 2026 texts), so "any specific organizational ideas should be strictly exempt"; and make it easy to apply
the members' own STIGs "as a part of a gpo for Windows or Linux systems". "CA" means fabric's own certificate
authority, step-ca and OpenBao, held to DISA's general guides (the owner confirmed). The work is its own release after
802.1X, started now and added to each area as features are built there.

## 1.18.1.3 The guides

Versions as DISA's library listed them on 2026-10-22 (read through the cyber.trackr.live mirror and NIST's National
Checklist Program: DISA's own pages at `https://public.cyber.mil/stigs/downloads/`, now
`https://www.cyber.mil/stigs/downloads/`, render only in a browser; 2.3.18.1). DISA releases quarterly; each version is
confirmed against DISA's download when its rows are written (1.18.2.6).

### 1.18.1.3.1 The five the owner named

| Guide | Version | Released | Rules (CAT I / II / III) | Applies to |
|---|---|---|---|---|
| Application Security and Development STIG (ASD) | V6R5 | 2026-09-30 | 286 (34 / 230 / 22) | the code fabric writes, and the applications it ships as they are configured |
| Application Programming Interface (API) SRG | V1R1 | 2025-09-11 | 65 (3 / 62 / 0) | every API fabric serves or drives |
| Application Server SRG | V4R6 | 2026-09-30 | 137 (14 / 123 / 0) | every server process that serves people or programs over the network |
| Domain Name System (DNS) SRG | V4R3 | 2026-09-30 | 119 (5 / 114 / 0) | the DNS parts, through the BIND STIG where it applies |
| BIND 9.x STIG (the DNS SRG for BIND) | V3R4 | 2026-09-30 | 73 (3 / 70 / 0) | BIND authoritative and the BIND resolver |

The BIND STIG is the DNS SRG made concrete for BIND, so for fabric's two BIND servers its rules are the answer and the
SRG's rules stand only where it has no BIND rule; for the DNS filter (AdGuard Home, which has no STIG) the SRG applies.

### 1.18.1.3.2 The certificate authority

DISA publishes no current STIG or SRG for a certificate authority product (none in the 2026 library; 2.3.18.1.3). As
the owner set, step-ca and OpenBao (which holds the CA's and fabric's other secrets, 1.7.1) are held to the general
guides: the Application Server SRG (certificate path validation, V-204754; private keys, V-204755; encryption of data
at rest, V-204770), the ASD STIG (key and signature cryptography, V-222570, V-222571; data at rest, V-222588; approved
CAs, V-222584, answered by fabric's own CA), and the API SRG (keys and tokens: V-274603, V-274606, V-274830, V-274712,
V-274783). The members' OS STIGs' trust items (DoD roots in the trusted store) are exempt and fabric's root takes their
place (1.18.3.2.3).

## 1.18.1.5 The exemption: requirements of the DoD as an organisation

### 1.18.1.5.1 What is exempt

A requirement, or the part of one, that only makes sense inside the DoD (DoW) as an organisation is answered
**exempt-DoD** in the checklist, with which kind below:

1. **DoD texts:** the Standard Mandatory DoD Notice and Consent Banner's wording (ASD V-222434 to V-222436, AS V-204713,
   V-204714, the OS STIGs' banners).
2. **DoD PKI:** DoD root, intermediate, Interoperability and ECA certificates in trust stores; "only DoD PKI-established
   CAs" (AS V-204811, V-204832; DNS SRG V-205213; the OS STIGs' certificate rules). fabric's own CA takes their place.
3. **DoD and federal identity cards and enterprise identity:** CAC, PIV, Alt. Token, FICAM, DoD enterprise ICAM (ASD
   V-222524 to V-222528, V-222557 to V-222560; AS V-204745, V-204800, V-204801, V-204807; API V-274559; the OS STIGs'
   smart-card rules). fabric's per-user certificates and passkeys (2.1.6.21) are its own way to the same end.
4. **DoD roles and processes:** ISSO, ISSM, Authorizing Official approvals, PPSM registration, IAVM, RMF packages,
   training records (ASD V-222627 to V-222629; BIND V-272382's AO approval; AS V-204718).
5. **DoD figures:** periods, intervals and counts that are DoD policy rather than a security property: "DoW-defined"
   event lists, backup and retention intervals, "DoW-required" frequencies (ASD V-222638; DNS SRG V-205160's event
   list); the security property behind each stays (1.18.1.5.2).
6. **DoD networks and services:** forwarding only to DoD or U.S. government resolvers (BIND V-272392), the Enterprise
   Recursive Service, DREN, `.mil` rules, DoD-approved time sources, DoD-licensed tools (HBSS/ESS, Trellix ENS).
7. **Classification:** marking classified output or security labels (ASD V-222393 to V-222395, V-222643).

### 1.18.1.5.2 What is not exempt

The technical requirement under a DoD wrapper stays: a banner of the organisation's own (2.1.18.8), trust in fabric's
own CA, strong sign-in for administrators (2.1.18.7), audit records that someone is told about when they fail (the
person fabric names in place of the ISSO, 2.1.18.5), backups and log offload at fabric's own intervals, forwarding to
the resolvers the install chose. "DoD-approved cryptography" and FIPS 140 validation are a federal requirement, not a
DoD one; how far fabric meets them is open (2.1.18.9). How strictly the exemption is read, whole requirement or only
its DoD part, is open (2.1.18.5); the recommendation is the DoD part only.

### 1.18.1.5.3 Why

fabric is for organisations that are not the DoD: a DoD banner, DoD roots or a CAC requirement would be wrong for them,
and DoD processes have no one to carry them out. The owner: "we are NOT a dod / dow organization any specific
organizational ideas should be strictly exempt" (2.1.18.2).

## 1.18.1.6 When the work is done: each feature, then 0.11.0

- **From 2026-10-22, each feature** applies its part's rows as it is built and updates them in the same change
  ([1.1.6.5](1.1.6-must-keep-working.md#1165-its-areas-stig-requirements)): 0.9.0's DHCP work answers `kea`'s rows,
  0.10.0's 802.1X work `freeradius`'s, the console's work `webui`'s.
- **0.11.0** closes the rest: every row left "to build" is built or answered, the second pass of 2.1.18.4 if the owner
  chooses it, the per-rule pass of 2.1.18.17, the STIG baselines for members (1.18.3), and the lab campaign that proves
  them (2.1.18.16).

## 1.18.1.7 Open points

The decisions 2.1.18.4 to 2.1.18.21 wait for the owner; nothing is built around them (Rule 13).
