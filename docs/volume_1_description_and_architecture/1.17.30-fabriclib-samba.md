### 1.17.30.39.4 `sync_rodc_cache(v, secrets=None, container='samba')`

| | |
|---|---|
| Purpose | at a site whose DC is read-only, cache the site's people and machines there so they sign in while the link to the writable DC is down (decision 2.1.6.55, manual 1.6.11.14): the read-only DC's lists checked (the cache group allowed, the denied list whole), the site's `<site>-rodc-cache` group kept at the writable DC as the site's agent (its people groups nested, its machines members, nothing else), then the site's own accounts preloaded. Idempotent: a second run changes no membership (the preload only refreshes). A person or machine removed from the site leaves the group's reach and is cached no more. |
| Inputs | v — fabric vars (site_name, ad_dc_type, ad_join_server, dc_name, ad_domain, ad_base_dn); secrets — fabric's secrets (default: load_secrets()); container — the DC's container. |
| Returns | list of str, what was done ([] where the site's DC is not read-only). |
| Fails | ValidationError: no writable DC known, the lists not as needed, the writable DC refusing or not answering (run_op's messages), the preload failing; and, after the rest is done, accounts of another site or of the organisation reached through the site's groups (named, with the group to remove them from: never preloaded). |
| Feeds | setup/start_services (after the join), deploy/restart_changed (every apply), samba/run_domain_command (`fabricctl domain rodc-cache`, the fabric-rodc-cache timer). |
| Called by | `fabriclib.deploy.restart_changed.restart_changed`, `fabriclib.samba.run_domain_command._rodc_cache`, `fabriclib.setup.start_services.run` |
