## 1.1.5.1 One operation per file

The global Rule 1 applies; fabric holds itself to its strictest form (stricter is allowed, Rule 13). Moved from
`AGENTS.md` §2–§3 on 2026-10-03.

- **Every distinct function or operation lives in its own file**, named for what it does (`verb_noun`):
  `dns/add_record.py`, `pki/issue_client_cert.py`, `vault/add_kmip_slot.py`. A reader finds the code for an
  operation from its name alone.
- Small private helpers used by exactly one function stay in that function's file. A helper used by two or more
  files moves to its own file in that folder's `common/` (or the top-level `common/` when it crosses domains) —
  still one helper per file.

## 1.1.5.2 Domain folders and their READMEs

- **Files are grouped by domain in folders** (`dns/`, `dhcp/`, `pki/`, `ldap/`, `keycloak/`, `vault/`, `secrets/`,
  `images/`, `security/`, `setup/`, `radius/`, `logs/`, `rbac/`, `system/`, `consent/`, `undo/`, `common/`, …).
  Prefer a new folder over a crowded one.
- Python domain code is the package `fabriclib`, imported as `fabriclib.<domain>.<file>` — namespaced so it can
  never collide with system packages (dnspython is also `dns`).
- **Every folder has a `README.md`** with one line per file saying what it does, updated in the same change that
  adds, renames or removes a file (`tests/docs` checks it). These are indexes only: design belongs in the manual
  (2.3.1.5).

## 1.1.5.3 Entry points only route

CLI dispatchers (`fabricctl`), API routers (`fabric-agent`) and web handlers parse input and call one function
file; no business logic in them (global Rule 1). The large files that predated this were split in 2026-10
(stale-code S7, 2.3.1.5); the entry points that remain (`deploy.py`, `interactive.py`, `keycloak_bootstrap.py`,
`manage.sh`, `agent/server.py`, the web UI's `server.py` and `devserver.py`) only route: keep it that way.

## 1.1.5.4 Docstrings and the function reference

Every function carries a structured docstring — Purpose, Inputs, Returns, Fails, Feeds (2.1.1.17) — from which the
function reference (1.17) is generated; `tests/docs` refuses a function without one.

## 1.1.5.5 Stale code

The global Rule 1 decides: code with no possible value is deleted in the same change (the commit says what and
why); code that might still be useful is recorded in the stale-code register (2.3.1.5) for the owner. Before
calling code stale, search for callers across the repository — templates, systemd units, tests and the manual
too — not only the file's own language. Documentation that describes something gone is stale too: fix it, or
register it when the fix waits on a decision.

## 1.1.5.6 Prompts go through ask(), with a stable ID

Every question fabric asks a person goes through `fabriclib/common/ask.py`: `ask("<area>.<name>", prompt, default)` for
an answer, `ask_secret("<area>.<name>", prompt)` for one that is not echoed. The ID is stable (a question keeps it when
its wording changes) and is how the entry-point inventory lists it and tests claim it (3.1.2.5, decision 2.1.1.38).
A prompt asked in a loop over keys takes its ID from the key (`menu.vars.<key>`). The lint suite fails on `input(` or
`getpass(` anywhere else in `src/`. Designed 2026-10-10 for 0.9.

## 1.1.5.7 A value goes into a file quoted for that file's language

A template never puts a setting into a file as it is. Every value a person can type is written so that, whatever it
holds, it is read back as that value and nothing in it runs:

| File | How | Where |
|---|---|---|
| YAML or JSON (`vars.yaml`, service configs) | `{{ value \| to_json }}`: a JSON string, also valid YAML | free-text settings in `templates/vars.yaml.j2` |
| a page (`*.html.j2`) | escaped automatically (the environment's autoescape for `.html.j2`) | `templates/nginx/www/` |
| a shell script (`*.sh.j2`) | `{{ value \| sh }}` (`shlex.quote`), never inside `"…"` | the client scripts in `templates/nginx/www/certs/` |

A value checked against a strict rule (a host-name label, an address) may go in as it is, since the rule already
keeps out what could break the file. `tests/render.py` proves it for the free-text labels with a label that holds
`: `, `#`, quotes, `$(…)`, backticks, HTML and a newline. Adopted 2026-10-10 (2.3.1.14).
