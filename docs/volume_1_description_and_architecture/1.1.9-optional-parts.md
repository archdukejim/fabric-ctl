## 1.1.9.1 Log forwarding (optional)
| Variable | Default | Notes |
|---|---|---|
| `install_fluentbit` | `false` | Fluent Bit forwards the journal and OpenBao's audit log (operations.md → Log forwarding) |
| `log_forwarding` | `{}` | `syslog: {host, port 6514, tls true, ca_file}`, `elastic: {url, user, index, ca_file}`, `hosts: {name: address}`, `buffer_limit: 256M` |
| `ip_fluentbit` | `10.255.0.95` | On fabric_net (metrics for `fabricctl logs status`) |
| `fluentbit_mem_limit` | unset (planned, 1.2.4.3) | Container memory limit: set, it fixes the limit |

The Elasticsearch password is not a setting: `sudo fabricctl logs set-password elastic` keeps it in OpenBao.

## 1.1.9.3 People's Linux identities (POSIX)
Design [1.6.3.9](1.6.3-samba-directory.md#1639-posix-identities) (identities in AD). The `uidNumber` range starts at the `users` OU's `uid_range` (`ldap_organizational_units`); each site has its own id block.

| Variable | Default | Notes |
|---|---|---|
| `posix_home_base` | `/home` | Home folder of each person: `<posix_home_base>/<uid>` |
| `posix_login_shell` | `/bin/bash` | Login shell given with the identity |

## 1.1.9.4 Time (NTP)
Design [ntp.md](1.13.1-chrony.md#11311-status); operations.md → Time. chrony on the host.

| Variable | Default | Notes |
|---|---|---|
| `ntp_servers` | `["time.cloudflare.com nts", "nts.netnod.se nts", "ptbtime1.ptb.de nts"]` (three independent sources: chrony outvotes one that is wrong) | `"<host> [nts] [pool] [prefer]"` (nts: authenticated time). A federated site asks its upstream site first. `[]`: the upstream site only, or this host's own clock |
| `ntp_serve` | `true` | Answer the network (`lan_cidr`, `security.firewall_allow`, the DHCP subnets) on UDP 123; `ntp.<domain>`; Kea hands it out (option 42) |
| `ntp_set_clock` | `true` | `false`: chrony keeps time but never sets the clock (a container sharing its host's kernel clock) |
| `hostname_ntp` | `ntp.<domain>` | Clients' name for the time server, a CNAME to the host (not added when you have a record of that name); `cname_ntp` (default `ntp`) changes the first label |
| `dhcp.ntp` | `[host_ip]` | Time servers Kea hands out (IPv4); `[]` hands out none |

## 1.1.9.6 DHCP (optional)
| Variable | Default | Notes |
|---|---|---|
| `install_kea` | `false` | Kea 3.0 LTS serves DHCP (operations.md → DHCP) |
| `dhcp.interfaces` | — | Host interface(s) to serve, e.g. `[eth0]`; UDP 67 is opened on them only |
| `dhcp.subnets` | — | `[{subnet, id, name, vlan, notes, pools: ["a - b"], routers, options, reservations: [{mac, ip, hostname, options}]}]`; `id` is Kea's subnet id (stored by fabric on the first change; leases are tied to it), `name` one label unique per site, `vlan` 1–4094 unique (a record only), `notes` up to 500 characters, `allow_overlap` why it may overlap another site's network (federation's address plan, up to 200 characters); no subnet may overlap `fabric_subnet`; pools do not overlap; reservations inside the subnet, outside its pools |
| `dhcp.options` | `[]` | Options for every subnet: `{name \| code, data, space, csv_format, always_send}`; one named like fabric's own (`domain-name-servers`, `ntp-servers`, `domain-name`, `domain-search`) replaces it |
| `dhcp.option_defs` | `[]` | `{name, code, type, space, array, record_types}`: options Kea has no name for |
| `dhcp.client_classes` | `[]` | `{name, test (Kea expression), options, next_server, server_hostname, boot_file_name}` |
| `dhcp.lease_time` | `86400` | Seconds, 300 to 2592000 |
| `dhcp.dns` | `[host_ip]` | DNS servers handed to clients |
| `dhcp.domain` | `domain` | Domain name handed to clients |
| `dhcp.ddns` | `true` | Register client hostnames in DNS |
| `dhcp.ddns_subdomain` | `dhcp` | The dynamic zone is `<ddns_subdomain>.<domain>` |
| `ip_kea_ddns` | `10.255.0.97` | kea-dhcp-ddns on fabric_net (sends the updates to BIND) |
| `kea_mem_limit` | unset (planned, 1.2.4.3) | Memory limit per Kea container: set, it fixes the limit |

The DDNS key's secret is generated (`kea_ddns_secret`, in OpenBao); it is not a setting.

## 1.1.9.8 The directory (Samba AD, required)
Design [1.6.5](1.6.5-samba-dc.md#1651-status) and [1.6.3](1.6.3-samba-directory.md#1631-status).
Every install runs a Samba AD domain controller on the host's address (host network, 2.1.6.18), Windows machines or not;
setup asks the domain and the password policy when they are not set, and an unattended setup refuses without them.

| Variable | Default | Notes |
|---|---|---|
| `ad_domain` | none: **required** | The AD domain, chosen once on the first node and permanent (2.1.6.11). Suggested: a sibling of fabric's domain at the top of the organisation's name (`lan.example.org` → `ad.example.org`); fabric's own domain or a parent of it is refused (same-domain mode was dropped) |
| *(examples)* | | With fabric's domain `lan.example.org`: `ad.example.org` (the suggestion, beside it) and `ad.lan.example.org` (inside it) work; `lan.example.org` (fabric's own) and `example.org` (a parent of it) are refused. BIND serves the AD zone either way, and the DNS filter forwards it |
| `ad_realm`, `ad_base_dn` | computed | The Kerberos realm (`ad_domain` upper-cased) and the base DN (`DC=` per label); cannot be set |
| `dc_name` | chosen by fabric: `dc-0001` for a new domain; a joining site's, the lowest free `dc-NNNN` given by its upstream, up to `dc-1999` (2.1.6.63, 2.1.6.65) | The domain controller's own name in the domain (`hostname_dc` is `<dc_name>.<ad_domain>`). Not a setting a person sets: never asked, and a settings file naming it is refused for a new install; permanent: an installed DC keeps its name (0.7.x's `dc-<host>` included; [1.6.5.26](1.6.5-samba-dc.md#16526-dcs-numbered-dc-nnnn-each-with-its-own-id-range)) |
| `ad_netbios` | the domain's first label | The NetBIOS domain name, at most 15 characters, upper-cased; fixed after provisioning |
| `hostname_dc` | `<dc_name>.<ad_domain>` | The DC's name in AD's domain (computed; the host's own name until 0.7.0) |
| `ad_password_policy` | none: **required** | The domain's password policy (2.1.6.13), every key: `minimum_length` (0–64), `complexity` (true/false), `history`, `minimum_age_days`, `maximum_age_days` (0: never), `lockout_threshold` (0: never), `lockout_minutes`, `lockout_window_minutes` |
| `ad_tier_password_policies` | copies of `ad_password_policy`, added by setup | The tiers' own policies (2.1.6.71): `enterprise_admin` (fabric-admin's; lockout never 0) and `directory_admins`, each with every key of `ad_password_policy`; set only with `sudo fabricctl domain password-policy --tier` ([1.6.12.16](1.6.12-domain-management.md#161216-what-d2-built-080)) |
| `ad_old_password_minutes` | `0` | How long AD accepts a previous password for network sign-ins after a change (2.1.6.15; AD's own default is 60) |
| `ad_dc_type` | `writable` | A site's DC: `writable` or `rodc` (read-only); from the invitation (`--dc`). The root's is always writable |
| `ad_join_server`, `ad_join_server_name` | `''` | A joining site: the root DC's address and name, from the join's answer (setup writes them) |
| `posix_id_range` (retired) | — | **Retired in 0.8.0** (D1, 2.1.6.86): not rendered, not read; a DC's range is its number's ([1.6.13.10](1.6.13-access-by-grants.md#161310-what-d1-built-080)) |
| `ad_site_ou` (retired) | — | **Retired in 0.8.0** (D1, 2.1.6.86): not rendered, not read; there are no site OUs (1.6.13.2) |
| `ad_org_ou` (retired) | — | **Retired in 0.8.0** (D1, 2.1.6.86): not rendered, not read; there is no `OU=organisation` (1.6.13.2) |
| `host_join_domain` | `true` | Whether setup makes this host a member of its own domain (no domain account but `fabric-admin` signs in to it, 2.1.6.78; local accounts untouched): true or false, asked in setup's Advanced; false is shown as a relaxation ([1.6.11.8](1.6.11-host-access.md#16118-the-fabric-host-as-a-member-of-its-domain)) |
| `host_machine_password_renew_days` | `0` | Days after which sssd renews the fabric host's machine password with adcli (installed by setup's `member` step when on); 0 is off (the password is set once and kept). A whole number from 0 to 999 ([1.6.11.12](1.6.11-host-access.md#161112-renewing-the-hosts-machine-password-071)) |
| `ad_ntp_signd_dir` | `/var/lib/samba/ntp_signd` | Where the DC's time-signing socket is shared with the host's chrony, which signs Windows members' time (2.1.13.1); the one folder Ubuntu's AppArmor profile lets chronyd use |
| `ad_rpc_ports` | `49152-49251` | The DC's RPC port range (narrowed from AD's 49152–65535), opened in the firewall |
| `posix_id_start` (retired) | — | **Retired in 0.8.0** (D1, 2.1.6.86): not rendered, not read; dc-0001's range starts at 1000000 ([1.6.3.17](1.6.3-samba-directory.md#16317-the-ranges-inside-a-dcs-id-range-070)) |
| `posix_id_block` (retired) | — | **Retired in 0.8.0** (D1, 2.1.6.86): not rendered, not read; every DC's range is a million ids (2.1.6.63) |
| `samba_mem_limit` | unset (planned, 1.2.4.3) | Container memory limit: set, it fixes the limit |

## 1.1.9.9 DNS filter: the BIND resolver
Design [1.12.2](1.12.2-bind-resolver.md#11221-status) (decision 2.1.12.3). On by default since 0.7 (it replaced
AdGuard Home); operations: 4.12.1.2.

| Variable | Default | Notes |
|---|---|---|
| `dns_filter` | `bind` (2.1.12.3) | `bind`: the resolver answers clients on `host_ip:53` and BIND moves to `bind_dns_port` 5053; `none` turns it off. 0.6's `adguard` is moved by `fabricctl setup` (2.3.12.1.9) |
| `install_resolver` | computed | `dns_filter == bind` (cannot be set) |
| `dns_filter_lists` | AdGuard DNS filter | `[{name, url, enabled}]`: the site's lists, matched by AdGuard Home from fabric's copies; unticked lists stay (`enabled: false`); `[]` = none (1.12.3.5) |
| `dns_filter_allow` | `[]` | Names allowed past every list, each with every name below it |
| `dns_filter_block` | `[]` | Names blocked whatever the lists say, each with every name below it |
| `dns_filter_upstreams` | Cloudflare: `[{address: 1.1.1.1, name: cloudflare-dns.com}, {address: 1.0.0.1, …}]` | AdGuard forwards to each address over DoT, the certificate verified for it; at least one (1.12.3.2) |
| `dns_filter_safe_search` | `false` | Strict safe search for everyone: Google, YouTube, Bing, DuckDuckGo, Yandex, Pixabay, Ecosia at once (1.12.2.15) |
| `dns_filter_youtube` | `strict` | YouTube's level while safe search is on: `strict` or `moderate` |
| `dns_filter_groups` | `[]` | Client groups: `[{name, clients: [IPv4 addresses, subnets], safe_search, youtube, allow, block}]`, each only adding to everyone's; the most specific address wins; no lists of their own (1.12.2.15, 1.12.3.6) |
| `ip_resolver` | `10.255.0.33` | On fabric_net |
| `resolver_mem_limit` | unset (planned, 1.2.4.3: 128 MiB) | Container memory limit: no lists in it (1.12.3.9); set, it fixes the limit |
| `ip_adguard` | `10.255.0.34` | AdGuard Home on fabric_net, nothing published (1.12.3.3) |
| `adguard_mem_limit` | unset (planned, 1.2.4.3.5: its share × 2.5, 980 MiB at 4 GB) | AdGuard Home's container limit: in the memory budget since 0.7.1 (2.1.12.8); set, it fixes the limit and the budget counts it / 2.5; a list past its share is refused when ticked (1.12.3.9) |
