## 1.2.7.1 Status

The inventory decision 2.1.2.8 (checklist E3) asks for: what runs with privileges, and each container's added
capabilities. Written 2026-10-04 with the Samba design and **confirmed by the owner the same day**: it settles 2.1.2.8, and any
change to it is a design change (Rule 13). Changed once since: the DC's NET_BIND_SERVICE (owner, 2026-10-04). Hardening rules: [1.2.4.1](1.2.4-containers.md#1241-container-hardening);
the `hardening` suite checks every container against this table.

## 1.2.7.2 Host services with privileges

| Service | Runs as | Why | Limited by |
|---|---|---|---|
| `fabric-agent` | root (systemd) | the only privileged worker: Docker (compose up/down, exec into fabric's containers), fabric's files, host changes recorded by setup | a unix socket for the web UI's uid only; a fixed route table (1.3.3), each route checked against the caller's permissions; no "run this command" |
| `fabric-federation` | root (systemd) | the federation endpoint: signs site CAs, writes the registry | its socket for nginx's uid only; join, rate- and size-limited (1.9.4.2) |
| `fabricctl` | root (an admin's sudo) | setup and operations | interactive; consent for host changes (1.2.9) |

Nothing else mounts the Docker socket, and nobody is added to the `docker` group (1.2.8).

## 1.2.7.3 Containers

Every container: `cap_drop: ALL`, `no-new-privileges`, read-only root, a memory limit. Users are the `fabric-*`
accounts of 2.1.2.4 (`service_users`). Limits are planned as a budget (1.2.4.3).

| Container | User (uid) | Added capabilities | Network | Memory at 4 GB |
|---|---|---|---|---|
| `nginx` | fabric-proxy (602) | none | `fabric_net`, ports 80, 443 | 256 MiB |
| `bind9` | fabric-dns (600) | none | `fabric_net`, port 53 | 80 MiB |
| `step-ca` | fabric-ca (603) | none | `fabric_net` | 50 MiB |
| `samba` | **root in the container** | **CHOWN, DAC_OVERRIDE, FOWNER, SETUID, SETGID, NET_BIND_SERVICE** | **host**, LAN interface only (2.1.6.18) | 512 MiB |
| `postgres` | fabric-db (605) | none | `fabric_net` | 200 MiB |
| `keycloak` | fabric-sso (604, gid 0) | none | `fabric_net` | 1200 MiB |
| `webui` | fabric-webui (606) | none | `fabric_net`, no ports | 96 MiB |
| `openbao` | fabric-vault (607) | none | `fabric_net` | 256 MiB |
| `fluentbit` (optional) | fabric-logs (608) | none | `fabric_net` | 64 MiB |
| `kea-dhcp4` (optional) | **root in the container** | **NET_RAW, NET_BIND_SERVICE** | **host** (DHCP needs the LAN interface) | 128 MiB |
| `kea-ddns` (optional) | fabric-dhcp (609) | none | `fabric_net` | 128 MiB |
| `freeradius` (optional) | fabric-radius (610) | none | `fabric_net`, UDP 1812/1813 | 128 MiB |
| `bind9-resolver` (the DNS filter, on by default; 2.1.12.3, replaced `adguard` and `oauth2-proxy` in 0.7) | fabric-resolver (613) | none | `fabric_net`, port 53 (BIND moves to 5053) | 384 MiB |

The exceptions are `kea-dhcp4` (Kea cannot drop privileges) and `samba` (a DC switches identities; 1.2.7.4).

## 1.2.7.4 What changes with Samba AD

From build step S1 ([1.6.5](1.6.5-samba-dc.md)); `dirsrv` left at S7 (0.5.0, 2026-10-05).

| Container | User | Added capabilities | Network | Memory at 4 GB |
|---|---|---|---|---|
| `samba` (every install) | **root in the container** | **CHOWN, DAC_OVERRIDE, FOWNER, SETUID, SETGID, NET_BIND_SERVICE** | **host**, LAN interface only (2.1.6.18) | 512 MiB |
| `bind9` | fabric-dns (600) | none | `fabric_net`, port 53; the DC's `smb.conf` and `bind-dns` read-only | **128 MiB** |
| `freeradius` | fabric-radius (610) | none | `fabric_net`; the DC's winbind sockets, its privileged pipe (FreeRADIUS's group only) and its `smb.conf`, read-only (PEAP, S3.3) | 128 MiB |
| `dirsrv` | — | — | removed at S7 | — |

Why the DC needs what it has: a DC switches to each user's identity for file access (SETUID, SETGID) and writes
Windows ACLs on SYSVOL when Group Policy changes (CHOWN, DAC_OVERRIDE, FOWNER), and binds its low ports in the
host network, where Docker's unprivileged-port setting does not apply (NET_BIND_SERVICE: added by the owner on
2026-10-04 after the test Pi showed it, S1.7); the first five proven necessary and sufficient
by the spike (Q1, Q16). Why the host network: 1.6.5.4.
