# 1.6.9 The organisation and its directory

Topics:
- 1.6.9.1 Organisation and directory settings

## 1.6.9.1 Organisation and directory settings
These settings name the organisation and shape what fabric keeps in its directory, the Samba AD domain (design
[1.6.3](1.6.3-samba-directory.md); the domain's own settings:
[1.1.9.8](1.1.9-optional-parts.md#1198-the-directory-samba-ad-required)). Convergence applies them on every setup and
apply: it adds what is missing and never deletes what an admin made.

### 1.6.9.1.1 `ldap_base_dn`
**Description:** The organisation's name in directory form. Since the move to AD it no longer names a directory tree
(the domain's own DN is `ad_base_dn`); invitations carry it, and a site joining an upstream must have the same one, so
it marks which organisation a site belongs to. Choose it when the root site is installed, e.g. `ldap_base_dn: dc=lan`
— `dc=` or `o=` first, then any `dc=` parts, lower case. A site that joins an upstream gets the upstream's. Fixed at
install: setup refuses to change it on a live install (marker `config/.ldap-base-dn`).

**Default Value:** one `dc=` per label of `org_domain`, e.g. `dc=lan,dc=example,dc=com` for `lan.example.com`

**Effected Jinja Templates:**
- `vars.yaml.j2`

### 1.6.9.1.2 `site_name`
**Description:** This install's site name (design [federation.md](1.9.1-sites.md#1911-status)): names its OU in the domain, `OU=<site_name>,OU=sites`, which holds its people, groups, machines, devices, device roles, networks, sudo rules and service accounts. One host-name label, lower-cased, and never `organisation`. Fixed at install: setup refuses to change it on a live install (marker `config/.site-name`).

**Default Value:** `hostname`

**Effected Jinja Templates:**
- `vars.yaml.j2`, `freeradius/config/fabric-radius.json.j2`, `nginx/www/certs/join-linux.sh.j2`

### 1.6.9.1.3 *[DELETED]* `ldap_local_dn`
This item has been removed from scope of fabric as of (0.5.0 / 2026-10-05). See 1.6.9.1.2 for newest applicable
method: a site's part of the directory is its OU in the domain.

### 1.6.9.1.4 `org_domain`
**Description:** The organisation's domain: names the organisation (`ldap_base_dn`) and is shared by every site of a fabric (design [federation.md](1.9.1-sites.md#1911-status)). A standalone install's is its own `domain`; a site that joined an upstream (`fabricctl setup --join`) gets the upstream's. Fixed at install: setup refuses to change it on a live install (marker `config/.org-domain`).

**Default Value:** `domain`

**Effected Jinja Templates:**
- `vars.yaml.j2` (the default `ldap_base_dn`)

### 1.6.9.1.5 `federation_endpoint`
**Description:** Run the federation endpoint other sites join through: the `fabric-federation` service (unix socket), an nginx vhost at `hostname_federation` (join route rate- and size-limited), its certificate and a CNAME. Turn it on and off with `fabricctl federation enable|disable` (which also issues the certificate). Off: no new site can join; sites that joined stay.

**Default Value:** `false`

**Effected Jinja Templates:**
- `nginx/nginx.conf.j2`, `nginx/docker-compose.yml.j2` (socket mount)
- `systemd/fabric-federation.service.j2`
- `vars.yaml.j2` (the CNAME)

### 1.6.9.1.6 `hostname_federation`
**Description:** The endpoint's name, always computed: `cname_federation` (default `federation`; it can be set but is not written to `vars.yaml`) + `.` + `domain`. An invitation carries it; joining sites connect by address and check this name on the certificate.

**Default Value:** `federation.<domain>`

**Effected Jinja Templates:**
- `nginx/nginx.conf.j2`
- `vars.yaml.j2`

### 1.6.9.1.7 `ldap_groups`
**Description:** The organisation's groups, made by convergence in the root site's `OU=organisation` (`OU=groups`)
with their gid numbers; `users` is AD's Domain Users (gid 5000).

**Default Value:** `[{name: admins, gidNumber: 1100, permissions: [read, write, modify]}, ...]`

Defaults also include one group per fabric role bundle (design 2.1.6.1): `auditors`,
`network-operators`, `equipment-operators`, `pki-operators`, `helpdesk`. A
group with a `bundle:` key has that Keycloak composite role granted to it
(`keycloak_bootstrap.py`); add people to the group to give them the bundle.
The defaults also include `network-staff` (1120) and `network-guests` (1121),
the groups `radius_people` lets join by password (802.1X).

Your entries are merged with the defaults by `name`: an entry with a default's
name replaces it, and defaults cannot be removed.

**Effected Jinja Templates:**
- `vars.yaml.j2`
- `keycloak_bootstrap.py` (bundle grants)

### 1.6.9.1.8 `ldap_organizational_units`
**Description:** Where the organisation's id numbers start: the `users` entry's `uid_range` gives the root site's id
block (`posix_id_block` long, from its first number). Merged with the defaults by `name`, like `ldap_groups`. The
domain's own OU layout is fixed (1.6.3.4).

**Default Value:** `[{name: accounts, description: User Accounts}, ...]` — `users` starts at 5001

**Effected Jinja Templates:**
- `vars.yaml.j2`

### 1.6.9.1.9 *[DELETED]* Directory Policy
This item has been removed from scope of fabric as of (0.5.0 / 2026-10-05). See 1.1.9.8 for newest applicable
method: the domain's password policy (`ad_password_policy`).

### 1.6.9.1.10 *[DELETED]* Role Accounts
This item has been removed from scope of fabric as of (0.5.0 / 2026-10-05). See 1.6.3.7 for newest applicable method:
each site's service accounts in the domain (`ad_agent_password`, `ad_keycloak_password`, `ad_radius_password`).

**Example (`vars.yaml`):**
```yaml
ldap_groups:
- { gidNumber: 1100, name: admins, permissions: [read, write, modify] }
- { gidNumber: 1200, name: developers, permissions: [read, write] }
- { gidNumber: 1300, name: operations, permissions: [read, write] }
- { gidNumber: 5000, name: users, permissions: [read] }
```

### 1.6.9.1.11 `logon_policies`
**Description:** Who may sign in to the site's joined machines, per OU (design
[1.6.11.4](1.6.11-host-access.md#16114-who-may-sign-in-per-ou)): a map from an OU's path below the site's OU (`""` for
the site's OU itself, `machines`, `machines/servers/linux`, …) to the groups allowed at the keyboard (`console`) and remotely
(`remote`: RDP, SSH). `fabric-break-glass` and each machine's local Administrators are always added. The map must
name the site's OU or `OU=machines`, and those may not grant nobody; group names are checked against the domain by
the editor (`fabricctl domain logon`, the web console's Machines section), which is how it is normally changed. Null
keeps the site's log-on rights of before 0.9 (2.1.6.44).

**Default Value:** null; setup gives a fresh install `{machines: {console: [<site>-machine-admins], remote:
[<site>-machine-admins]}}` (2.1.6.42)

**Example (`vars.yaml`):**
```yaml
logon_policies:
  machines: {console: [lan-machine-admins], remote: [lan-machine-admins]}
  machines/servers/linux: {console: [lan-machine-admins, lan-devs], remote: [lan-devs]}
```
