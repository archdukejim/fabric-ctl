# 1.17.1 About the function reference

Topics:
- 1.17.1.1 What it is
- 1.17.1.2 How it is numbered
- 1.17.1.3 Keeping it current

## 1.17.1.1 What it is

Every function and method in fabric's own code (`src/`, `packaging/`, `scripts/install-from-checkout.sh`), generated from
its structured docstring (decision 2.1.1.17): purpose, inputs, returns, failures, what feeds on it, and who calls it
(found in the code). One subchapter per area of the code (1.17.2 onwards); each source file is a topic, each
function a sub-topic. Never edited by hand: change the docstring, then regenerate.

## 1.17.1.2 How it is numbered

Numbers follow 5.7 like every other chapter: they are given once and never reused. A committed registry,
`scripts/docs/lib_doc_numbers.tsv`, records the number of every area, file and function the generator has ever
seen. A new one takes the next number after the highest ever used at its level; one that is gone keeps its
number with a `[DELETED]` entry and the date it was found gone. So a function's number stays the same for as long
as the function exists, and a link to it keeps working.

Two branches merged together can each give their own new file the same next number. The generator refuses a
registry that gives one number twice at a level (two areas, two files of one area, two functions of one file),
naming both items; the fix is to delete the later-added item's row and regenerate, which gives it the next free
number (`tests/docs/lib_doc_registry_test.py`, part of the docs suite). The nine clashes such merges had left were
settled that way on 2026-10-13: the later-added file of each pair took the next free number.

## 1.17.1.3 Keeping it current

`python3 scripts/docs/gen_lib_doc.py` regenerates the subchapters, the registry and this chapter's list in the
Volume 1 index; `--check` (part of `tests/run-all.sh docs`) fails when they are not what the code says.
