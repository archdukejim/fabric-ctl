# 2.1.3 Decisions: fabricctl, setup and fabric-agent

Topics:

## 2.1.3.1 Python-in-.deb vs Go binary

- **Decision:** Python ([1.3.1.1](../volume_1_description_and_architecture/1.3.1-host-package.md#1311-package-design)).
- **Shapes:** 1.3, 1.1
- **Made:** 2026-09-27 to 2026-10-01, while fabric was designed, by the owner.
- **Why:** the package needs no build step and hosts can read what runs (2.3.1.8.2).
- **Status:** In force; built this way.

## 2.1.3.2 Product split and privilege model

- **Decision:** fabricctl (CLI + root `fabric-agent` — deliberately not `fabricd`, FRRouting's OpenFabric daemon — `fabric-admins` group, no docker group) and the Open Fabric web UI container; one repo, two artifacts ([1.1.1.3](../volume_1_description_and_architecture/1.1.1-what-fabric-is.md#1113-two-products-fabricctl-and-the-fabric-ctl-web-control)).
- **Shapes:** 1.3, 1.8
- **Made:** 2026-09-27 to 2026-10-01, while fabric was designed, by the owner.
- **Why:** the owner framed fabric as two products from the start (2.3.1.8.1).
- **Status:** In force, built differently: the CLI runs as root via sudo, `fabric-agent` serves only the web UI, no `fabric-admins` group (1.1.1.3).

## 2.1.3.3 Setup UX

- **Decision:** Default change list → Proceed / Advanced; everything settable in `vars.yaml`; `--non-interactive` ([1.3.2.1](../volume_1_description_and_architecture/1.3.2-setup-design.md#1321-setup-secure-by-default-fully-scriptable)).
- **Shapes:** 1.3, 3.3
- **Made:** 2026-09-27 to 2026-10-01, while fabric was designed, by the owner.
- **Why:** a person can accept sensible defaults in one step, and an unattended install can set everything in a file.
- **Status:** In force.

## 2.1.3.4 Setup with no terminal is refused before it asks anything

- **Decision:** `fabricctl setup` that would ask a question (not `--non-interactive`, `--doctor` or `--undo`, nor
  only steps that need no input) and finds no terminal on stdin (a pipe, `ssh -T`, a script) is refused before
  anything is asked or changed, exit 1, saying to run `sudo fabricctl setup --non-interactive --file FILE` (or
  `--non-interactive` alone for the defaults). `--file` alone still asks (Guided or Advanced, and what the file
  leaves out), so it is refused the same way ([1.3.2.4](../volume_1_description_and_architecture/1.3.2-setup-design.md#1324-setup-with-no-terminal-080)).
- **Shapes:** 1.3 (1.3.2.4), 3.3 (3.3.1.1.2)
- **Made:** 2026-10-24, by the owner ("yes"), from the DHCP lab campaign (`dev/0.9.0` note 2.3.10.11.16: setup
  with no terminal crashed with Python's `EOFError` at its Guided/Advanced question).
- **Why:** a refusal that says what to run instead is what an unattended caller can act on; a traceback is not.
- **Status:** In force; built 2026-10-24 (`setup/require_terminal`).
