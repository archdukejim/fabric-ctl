  file has been reviewed", caused by `HANDOFF.md` (not in the review ledger).
- **Documents:** a coverage check proves every line of every old document lands in exactly one manual file
  (headings renumbered, nothing else changed) before the old file is removed.
- **Code moves (Rule 7):** the installed tree outside `docs/` and the rendered templates must hash identically
  to the baseline; the test results must match.
- **Impact** (presented and approved 2026-10-03): no product design change in steps 1–6; breaking for the
  in-browser manual, about 187 references in 106 code and test files, the docs tools, and the package build.
  Scope creep risk: medium, held down by keeping the document move mechanical.

  not yet moved, so every file stays indexed; Rule 5.6 allows only volumes and chapters there, so the list is
  removed when the last document has moved. (Removed 2026-10-03: the function reference became 1.11 and the review ledger moved to Volume 5's

## 2.3.1.8 Why the checklist answers are what they are

### 2.3.1.8.1 Product shape (2.1.1.8, 2.1.1.9, 2.1.1.10, 2.1.1.11, 2.1.1.12, 2.1.2.3)

fabric exists to set up and run a network's core services on a host, so it is a host product (2.1.1.8). The owner
framed it as two products from the start, the `fabricctl` control and the Open Fabric web control (2.1.3.2), which
Rule 7.2 calls two UX variants; they share one package because the web UI is only a client of the agent the
package installs (2.1.1.9). Ubuntu LTS is what the reference Raspberry Pi and the test machines run (2.1.1.10). On 2026-10-04 the owner made it the
only host target, dropping Debian 13 and Raspberry Pi OS from 2.1.1.1: one large, widely supported distribution with a
long support cycle, backed by one of the largest groups, rather than a test matrix spread over three. The owner
requires arm64 for the Pi and amd64 for testing (2.1.1.11). There is no commercial edition (2.1.1.12). The 4 GB Pi budget
shaped every memory limit (2.1.2.3).

### 2.3.1.8.2 Code and repository (2.1.1.13, 2.1.1.14, 2.1.1.15, 2.1.1.16, 2.1.1.17)

Python was chosen over Go so the package needs no build step and hosts can read what runs (2.1.3.1, 2.1.1.13). One package
is enough for one product (2.1.1.14). ruff and shellcheck catch real errors in the code as written; a typecheck would
need annotations the code does not carry, so it waits (2.1.1.15, owner: "whatever you recommend"). The repository is
on GitHub and already builds in Actions (2.1.1.16). The structured docstrings and the generated reference were the
owner's choice on 2026-09-28 and are built (2.1.1.17).

### 2.3.1.8.3 Release and packaging (2.1.1.18, 2.1.1.19, 2.1.1.20, 2.1.14.4, 2.1.1.21)

`config/VERSION` already follows semantic versioning (2.1.1.18). On 2026-10-04 the owner noted that everything so far has been beta: the first release meant for users is the 1.0 milestone, after thorough testing of the whole stack (2.1.1.31). Semantic versioning orders a pre-release below its release (1.5.0-beta is still above 1.0.0), and v1.0.0 was already taken, so the earlier releases were renumbered to 0.x and later betas stay 0.x until 1.0.0. Releases already publish the `.deb` (2.1.1.2, 2.1.1.19). Only
the previous release must upgrade, because the owner rebuilds older installs instead of migrating them (2.1.1.20).
Digest pinning keeps an upstream push from changing what runs (2.1.14.3, 2.1.14.4). Building images on each host costs the
Pi time and makes hosts differ; the owner chose to publish fabric's own images and manage their updates (2.1.1.21,
2026-10-03).

### 2.3.1.8.4 Installed footprint (2.1.2.4, 2.1.2.5, 2.1.2.6, 2.1.1.22, 2.1.2.7)

The `fabric-*` names and the 600–649 band avoid Ubuntu's own accounts after the 26.04 upgrade asked to remove
`bind` (2.1.2.4). Every install already uses `/opt`, which 2.1.2.1 had wanted to change (2.1.2.5). Uninstall exports on request
because it removes the CA and the vault; downloaded images are kept because they are large and shared (2.1.2.6). The
owner insisted that offline must always work (2.1.1.22). The host-change groups are the consent design (2.1.2.7, 1.2.9).

### 2.3.1.8.5 Security (2.1.7.3, 2.1.6.2, 2.1.2.8, 2.1.2.9, 2.1.2.10)

OpenBao holds secrets so nothing sensitive sits in plain files after setup (2.1.7.1, 2.1.7.3). Keycloak with TOTP and a

### 2.3.1.9.2 Docker in WSL

What running the suites there has taught (2026-10-02 to 10-03):

- Call WSL with `MSYS_NO_PATHCONV=1` from Git Bash, and put any multi-line command in a script file: inline
  `bash -c` strings lose their escapes, and a `$(…)` in them is expanded on the Windows side.
- The distribution shuts down a few seconds after its last session ends, stopping detached containers (the
  sandbox exits 255) and restarting the owner's: keep a session open for the whole run.
- Never start a second `tests/run-all.sh` with the same `FABRIC_TEST_OUT` while one runs: run-all clears that
  folder. The dirsrv, keycloak and hardening suites need `render` in the same run.
- Never edit a test script while it runs: bash reads scripts as it goes.
- The WSL kernel can hang: processes stuck in `sync()` (state D on `super_lock`) never exit, 389-DS reports
  "already running as process N" and Docker cannot stop containers. Only `wsl --shutdown` clears it, which stops
  every distribution: ask the owner first.
- A Windows `git worktree` cannot be used from WSL (its `.git` file holds a Windows path): clone inside WSL.
- From Git Bash, Python defaults to the cp1252 code page: set `PYTHONUTF8=1` before it edits UTF-8 files.

### 2.3.1.11.4 Certificate revocation, for everything (2.1.5.10)

- Step-CA publishes a **CRL** (its built-in CRL, signed by the intermediate, regenerated on every revocation and at
  least daily), served on `certs.<domain>` (HTTP, like the CA files) and named in every certificate fabric issues
  (CRL distribution point) from 0.6.3 on.
- **Revoke** any certificate fabric issued — device, person, LAN machine (ACME), service, a federation site's
  intermediate — from the web console's PKI page or `fabricctl certs revoke <serial|name> [--reason R]`, permission
  `pki:revoke` (new; in the PKI operator's bundle). Every revocation is audited.
- **Checked by** FreeRADIUS (EAP-TLS: `check_crl = yes` with the CRL fetched into its config) and nginx (client
  certificates: `ssl_crl`), both refreshed by the certificate timer (2.1.5.4). A revoked device is refused at its next
  authentication even if it is still linked. Answers open decision 2.1.5.2 (federation site CAs).
- Unlinking a device stays the quick way to cut one off; revocation is the lasting one.

- **Image updates from the console:** an Updates section shows `fabricctl images status` and applies `update` or

### 2.3.1.11.6 The DNS leftovers (2.1.12.2, 2.1.14.13)

- **DNS-over-TLS on 853, by AdGuard** (2.1.12.2), so encrypted queries are filtered like the rest; its certificate is
  the DNS name's service certificate, or the public wildcard when that is on (2.1.5.9). Port 853 joins `ports`

- **A DoH health check:** doctor and the web console's Overview query `https://<dns name>/dns-query` for a name fabric
  serves and check the answer; the sandbox and host suites do the same.
- **A stale published image is detected** (2.1.14.13): the lock records each published image's **source hash** (its
  Dockerfile, its staged build context and its base image's digest). The images suite and CI refuse a change to an
  image's sources without the image marked `pending` (to be rebuilt and published), so a stale image cannot ship.

### 2.3.1.11.7 `fabricctl people` (2.1.6.30)

- `fabricctl people list | show <uid> | add <uid> --first F --last L --email E | reset <uid> | disable <uid> |
  enable <uid> | remove <uid> | groups <uid> | group add|remove <group> <uid>`, as root on the host (the audit names
  the CLI). A one-time password is printed once on the terminal, never logged.
- **Disable** blocks sign-in everywhere at once: the AD account is disabled and Keycloak's sessions for the person
  end. **Remove** asks for the uid typed back, removes the account and its Keycloak user; their issued certificates
  are revoked (2.3.1.11.4). Only the site's own people; fabric's built-in accounts are refused with the reason.
- The web console's People page gains disable, enable, remove and groups; permissions `people:disable`,
  `people:remove` and `people:groups` (new; disable in the Helpdesk bundle, the others admin).

### 2.3.1.11.8 Offline install bundles (2.1.14.14)

- `fabricctl images export --arch amd64|arm64 -o <file>` makes **one bundle per release and architecture**: fabric's
  `.deb`, the Ubuntu packages it installs (Docker and the rest, for the host's Ubuntu release), every image in the
  lock by digest (`docker save`), and their cosign signature bundles, with a manifest (versions, digests, hashes).
- `sudo fabricctl setup --offline <bundle>` (and `fabricctl images import <bundle>` on an installed host) checks the
  manifest's hashes and **every image's signature offline** (the bundled cosign bundles against fabric's identity,
  2.1.14.6), then installs the packages and loads the images; nothing is fetched. No local registry.
- An image or package whose signature or hash does not check is refused, with which one and why.

### 2.3.1.11.9 OpenBao's leftovers (2.1.7.4, 2.1.7.5)

- **Keycloak's database password rotates monthly** (2.1.7.4): Postgres gets its own admin user, separate from
  Keycloak's (which stops being a superuser); OpenBao's database engine owns Keycloak's password as a static role and
  rotates it on a monthly schedule, at night; fabric then renders Keycloak's settings and restarts it (about a minute).
  **Postgres never depends on OpenBao to start**: the password lives in Postgres; only a rotation needs OpenBao. A
  rotation that fails leaves the old password working and is a warning. `fabricctl vault rotate-db` rotates now.
- **An SSH certificate authority for the domain's Linux machines** (2.1.7.5), OpenBao's SSH engine:
  - **user certificates**, 8 hours, with the person's AD groups as principals (sudo still from AD's rules), from the
    web console (paste a public key, download the certificate) or `bao ssh` after signing in with Keycloak;
    permission `ssh:sign` (new, everyone signed in);
  - **host certificates** for joined machines (the join script asks for one; renewed by the machine's timer), so
    people's clients trust the domain's hosts without the first-connection prompt;
  - the join script trusts the user CA (`TrustedUserCAKeys`, an option, on by default) and installs a known-hosts
    line for the host CA. OpenBao off means no SSH CA, said so on the page.

### 2.3.1.11.10 The Linux join's leftovers (2.1.6.31)

- **Host groups:** AD groups in the site's `OU=groups` (`<site>-hosts-<name>`), machines as members; log-on rules per
  host group (which people's groups may log on), enforced through SSSD's GPO-based access as today. CLI `fabricctl
  machines groups | group add|remove <group> <machine>` and the web console's domain section; permission
  `machines:admin`.
- **Sudo rules:** an editor for custom sudo rules beyond the site's default: who (people or groups), which commands,
  as whom, on which host group; stored as AD sudo rules (SSSD's `sudo_provider=ad`), under the site's OU so nested
  sites inherit as today. CLI `fabricctl sudo list | add | remove`, web console; permission `sudo:admin` (new, admin
  bundle). A rule granting ALL to everyone is refused.
- **systemd-resolved:** the join script points resolved at fabric's DNS with the domain as search domain (1.6.7.5),
  keeping the machine's other links' DNS as they are; an option, on by default.
- The manual's drift is fixed with it (4.6.6 names `<site>-admins` where the code uses `<site>-linux-sudo`).
