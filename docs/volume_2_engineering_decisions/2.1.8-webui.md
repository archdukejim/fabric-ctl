## 2.1.8.1 The web UI from a domain device

- **Decision:** Signed in by the domain, then asks for TOTP by default.
- **Shapes:** 1.8, 1.6
- **Made:** 2026-10-07, by the owner.
- **Why:** 2.3.6.2.
- **Status:** Revised 2026-10-07 by 2.1.6.23: no second factor by default; TOTP or a passkey is raised from the web console.

## 2.1.8.2 The web UI's client certificate

- **Decision:** An **option, off by default**, easy to turn on after the first standup; status output and the web UI show whether it is on. (Before: always required, 2.1.6.2.)
- **Shapes:** 1.8, 1.5
- **Made:** 2026-10-07, by the owner.
- **Why:** the certificate made a first standup hard to use; it stays as a layer to raise (2.3.6.2).
- **Status:** In force; built in 0.6.1 (`webui_client_cert`).

## 2.1.8.3 Doctor and image updates on the web console

- **Decision:** The Overview runs the doctor checks on demand (`status:read`); an Updates section shows image status and applies update or rollback per service as a job (`images:update`, new, admin, behind the admin tools' second factor when raised).
- **Shapes:** 1.8, 1.14
- **Made:** 2026-10-08, by the owner, for 0.6.3.
- **Why:** 2.3.1.11.5.
- **Status:** In force; **built 2026-10-08** ([1.8.4.2](../volume_1_description_and_architecture/1.8.4-webui.md#1842-doctor-and-image-updates-on-the-overview)); the ACME page with it (Step-CA → ACME, 1.5.1.4). The pages for public certificates, dynamic DNS and the Linux join's leftovers move to 0.7 with those features (2.1.1.39), then to the release after it (2.1.1.42).

## 2.1.8.4 A settings page for setup's choices

- **Decision:** the web console gets a settings page where everything setup decided that is not permanent can be
  changed: the network and host name, the memory fabric may use, the optional services, the password policy,
  Kerberos sign-in, the host changes setup was allowed to make (undone or allowed again), and sign-in security,
  lowering included. Each change asks again for the password of the first admin (2.1.6.33), or later of a
  `fabric-admins` member (2.3.6.4). The permanent ones are shown, read only: the domain, the AD domain, the CA, the
  site and the organisation.
- **Replaced by 2.1.8.7 on 2026-10-14** (the owner, with its impact assessment): a wizard instead of a page, built in
  0.8.0 instead of 0.11, with the network, the host's name, the host changes and lowering sign-in security kept on the
  host's console.
- **Shapes:** 1.8, 1.3, 4.2
- **Made:** 2026-10-09, by the owner ("a menu to the web ui, that requires host password to change these things …
  it could be frustrating if they can't change them later"; everything not permanent; the first admin's password).
- **Why:** setup asks many questions once; each answer must be easy to change later, and changing the host's
  settings is worth proving again who is at the keyboard.
- **Status:** In force; to build in the release after 0.7 (moved by 2.1.1.42 on 2026-10-10; it was set for 0.7); **placed in 0.11 by 2.1.1.45 on 2026-10-10**. Revises 2.1.6.24 (lowering, today only on the host's command line). Its
  page layout and how each change is applied are designed with that work.

## 2.1.8.5 The console's navigation runs down the left, as Cockpit's

- **Decision:** the web console's frame mirrors Cockpit's: a top bar (the install, its host and version, the person
  signed in) and a navigation down the left, one entry per part with its pages below it, replacing the row of tabs;
  the pages' contents and routes stay ([1.8.3.2](../volume_1_description_and_architecture/1.8.3-single-pane.md#1832-the-consoles-frame-a-navigation-down-the-left-as-cockpit-has-it)).
- **Shapes:** 1.8
- **Made:** 2026-10-11, by the owner, reviewing `v0.8.0-rc.2` ("I really like the cockpit layout, could mirror that
  layout instead?"), for 0.9.
- **Why:** the parts outgrew a row of tabs; a navigation down the side holds them and their pages.
- **Status:** In force; to build in 0.9.

## 2.1.8.6 DNS is one entry with two pages: Zones and the DNS filter

- **Decision:** the console's DNS has one navigation entry with two pages, Zones (BIND9: zones, records, TSIG, ACLs)
  and the DNS filter; each page keeps its own permission, and the entry shows for anyone who may see either ([1.8.3.2](../volume_1_description_and_architecture/1.8.3-single-pane.md#1832-the-consoles-frame-a-navigation-down-the-left-as-cockpit-has-it)).
  The "optional" badges on the tabs go (already in 0.8.0-rc.3).
- **Shapes:** 1.8, 1.12
- **Made:** 2026-10-11, by the owner ("combine DNS filter into Bind9 DNS … two different top level tabs, so
  permissions are easier to manage"; one entry with two pages, over two separate entries).
- **Why:** one place for names, two permissions as today.
- **Status:** In force; to build in 0.9 with 2.1.8.5.

## 2.1.8.7 A setup wizard in the console, with a settings file; sensitive settings stay on the host's console

- **Decision:** setup's choices that are not sensitive are changed in a wizard in the web console (*Settings*), first
  after install and later to reconfigure, through one plan and one apply; the same settings export to and import
  from one file format, in the console and with `sudo fabricctl settings export|import` (owner: "same files, just
  two different methods"); an import ignores what is not the wizard's — secrets, console-only settings — listing it.
  The console-only set: the permanent identity, the network and the host's name, the first admin, every host change,
  OpenBao's unlock and recovery, lowering sign-in security, client certificates and every secret
  ([1.8.5.2](../volume_1_description_and_architecture/1.8.5-setup-wizard.md#1852-what-the-wizard-changes-and-what-stays-on-the-hosts-console)).
- **Shapes:** 1.8 (1.8.5), 1.6.8 (`settings:admin`), 1.3.2 (setup's last words), 1.1.4 (0.8.0).
- **Made:** 2026-10-14, by the owner: "for things that can get changed via the web ui (aka the non-permanent stuff)
  should we move that to a setup wizard in the webui and use that wizard to reconfigure the system in the future as
  well. Within limitation, certain sensitive items should be limited to the console"; then: replace 2.1.8.4 (yes),
  "in line with 0.8.0", the network and host name console-only (yes), headless through file import and export in the
  wizard and a fabricctl command, "certain WebUI fields will be ignored (such as passwords, etc)".
- **Why:** one place to change the site, a file to repeat it on another, and the settings that can cut the console
  off from its host, or touch its operating system, where only someone at the host can change them.
- **Status:** In force; to build in 0.8.0. Replaces 2.1.8.4. **Revised by 2.1.1.58 on 2026-10-17:** on 0.8.0 the
  wizard offers and writes no DHCP or address-manager setting; DHCP joins it with the address manager in 0.9.0.
