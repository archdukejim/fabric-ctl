## 2.2.2.1 Known issue of 0.8.0: a fresh install's setup stops at a unit's start (Postgres, Keycloak, nginx)

*Added 2026-11-01 (found by the lab campaigns, 2.3.10.11.24 and 2.3.1.33); revised the same day by the throttled-disk
proof (2.3.1.35, decision 2.1.1.76): the unit that stops it can be any whose start runs out of time on a slow disk,
nginx's among them, not only Postgres or Keycloak.* Applies to fabric **0.8.0** only, and only to a fresh install's
first `sudo fabricctl setup`: a host that is already installed is not affected, because the bug is in the services'
first start. 0.9.0 fixes Postgres's part (1.2.4.5). In the lab it stopped one fresh 0.8.0 install in three, and every
time on a disk throttled to 20 IOPS.

**What the operator sees.** Setup's start step stops partway with a failed start of one unit, for example:

```
Job for nginx.service failed because a timeout was exceeded.
See "systemctl status nginx.service" and "journalctl -xeu nginx.service" for details.
```

(or `Job for postgres.service failed because the control process exited with error code.`, or the same for
`keycloak.service`), followed by setup's own error naming that unit, `subprocess.CalledProcessError: Command
'['systemctl', 'start', '<unit>']' returned non-zero exit status 1.`, and "setup did not finish". `fabricctl doctor`
then fails. `journalctl -u keycloak` may show `Connection to postgres:5432 refused`.

**Cause.** A unit's start waits for its container's health (up to 10 minutes) and fails when Docker calls it
`unhealthy` or systemd's start times out. On a slow disk a first start (Postgres's `initdb`, a service's first run)
can take longer than that; and Postgres's probe answered too early (its temporary server), so Keycloak started
against a database not yet listening. See 1.2.4.5.

**Fix.** Run setup again, with the same settings file and flags if the first run was unattended; it resumes where it
stopped:

```
sudo fabricctl setup
```

Then `sudo fabricctl doctor` passes (proved on a still-slow disk, 2.3.1.35). Upgrading to 0.9.0 or later removes
Postgres's part of the cause.
