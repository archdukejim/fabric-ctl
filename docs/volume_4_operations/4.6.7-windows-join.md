## 4.6.7.1 What a joined machine gets

A Windows machine that joins the domain works at once (design: [1.6.5.20](../volume_1_description_and_architecture/1.6.5-samba-dc.md#16520-s5-in-detail)).
fabric's policies reach it at its next start:

- **Trust:** fabric's root CA is a trusted root, so fabric's sites, the web UI and 802.1X are trusted without
  importing anything.
- **Log-on:** who signs in at the keyboard or remotely, and who is a local administrator, is decided by the
  domain's grants (4.6.10): each set of machines gets its GPO, `fabric: access <n>`, with the sign-in rights and the
  administrators' groups; `BUILTIN\Administrators` and the machine's `local-admin` always sign in, and a machine no
  grant reaches admits nobody else from the domain. The machine waits for the network at start-up and log-on, so a
  person's first log-on reaches the domain controller.
- **Time:** the machine keeps its domain controller's time, signed by it (the fabric host's chrony answers for it).
- **802.1X** (when FreeRADIUS is on and a group is mapped): Wired AutoConfig is turned on and the network profile
  installed — PEAP to `radius.<domain>`, checked against fabric's CA — first as the machine, then as the person
  signed in. Map the machines' group (`fabricctl radius map-group "Domain Computers"`, with a VLAN if you want one)
  so they get on the network before anyone logs on.

## 4.6.7.2 Before joining

- The machine must find the domain: its DNS server is the site's fabric host (DHCP from fabric gives it), or at
  least the AD domain's names are sent there (an NRPT rule, as on host-1 in 2.3.6.1.14).
- Windows Pro, Enterprise or Education (Home cannot join a domain).
- A Directory Administrator's account (`directory-admins`), whose password they set at the web sign-in first.

## 4.6.7.3 Joining

Settings → Accounts → Access work or school → Connect → *Join this device to a local Active Directory domain*,
the AD domain (for example `ad.example.org`), then the Directory Administrator's user name and password. Restart.

The machine's account is made in `OU=machines`; within the hour fabric files it, once, by its edition: a Windows
Server into `OU=servers`, any other into `OU=desktops` (`fabric-machines.timer`, or now: `sudo fabricctl domain
sort-machines`; [1.6.13.10](../volume_1_description_and_architecture/1.6.13-access-by-grants.md#161310-what-d1-built-080)). A machine you move back is left there. `fabricctl domain add-machine <name> --type desktop`
(or `--type server`) pre-creates it in that type's OU and group. To keep it out of the default
place, or to join a machine with no line of sight to the domain controller, an offline join works too
(`djoin /requestodj`, as host-1 joined in 2.3.6.1.14).

## 4.6.7.4 After joining

- Windows puts a joined machine's network connection in the **Domain** firewall profile: rules you added to the
  Private profile (an SSH server, for example) need adding to the Domain profile too.
- `gpresult /r /scope computer` lists fabric's policies: the trust in fabric's root CA, `<site> Windows baseline`
  and the `fabric: access <n>` of its set of machines (4.6.10).

## 4.6.7.5 When it does not work

- *The domain could not be contacted*: the machine is not using the site's DNS for the AD domain (4.6.7.2).
- A person cannot log on: no grant gives them sign-in there (`sudo fabricctl domain grant explain <person>
  <machine>`, 4.6.10.5), or they have not set their own password at the web sign-in yet.
- No network before log-on on an 802.1X port: map the machines' group (4.6.7.1); the FreeRADIUS tab's recent
  decisions show `REJECT method=peap machine=<NAME>$` and why.
