## 4.5.2.1 Manual certificates

For the devices that cannot use ACME: switches, printers, appliances, VPN
boxes, Windows machines with `certreq`.

- **Signing policy.** The CSR's signature must verify. Its key must be RSA ≥ 2048,
  EC P-256/384/521 or Ed25519. Its names must be DNS names, IP addresses or
  e-mail addresses (URIs and other names are refused). Validity runs from 1 day
  to [`pki_manual_max_days`](../volume_1_description_and_architecture/1.5.2-pki.md#152116-pki_manual_max_days) (default 5 years).
  Whatever the CSR asks for, the result is a **leaf** (serverAuth + clientAuth)
  from fabric's template: a request for `CA:TRUE` is shown in the review and
  ignored. If the CSR has no SANs, the CN becomes one.
- **Generated keys are not kept.** A generated private key exists only in the
  response. It is shown once as PEM and as a `.p12` with a generated
  password. Downloads are `data:` links on the result page, so there is never
  a URL to fetch the key again. Nothing is written to disk except a 0600
  temp dir that is removed at once.
- **Inspect refuses private keys** unread. **Convert** uses a supplied key
  only to build the `.p12`, after checking it matches the certificate.
- **Ledger.** Every hand-issued certificate is recorded in
  `/opt/fabric/archive/issued-certs.jsonl` (0600): subject, names, serial,
  expiry, fingerprint, who issued it and how. The ledger holds no keys. Each
  issue is also written to the audit log (`PKI_SIGN_CSR`, `PKI_ISSUE`,
  `PKI_CONVERT`).
- Signing uses the Step-CA intermediate key through the pinned step image
  (`docker run --network none`), as setup does. The CA key never enters the
  web UI container.

## 4.5.2.2 In the console: issued certificates and their revocation

Design: [1.8.6.11.17](../volume_1_description_and_architecture/1.8.6-console-redo.md#18611-as-built).

- **PKI → Certificates → Issued** (needs `pki:read`): every certificate the console can revoke (from 0.10.0: 4.5.2.3),
  lit by its status (valid, expires soon, expired or revoked). Select one for its page: its names, how it was made, its serial and
  fingerprint, and the device it is linked to.
- **Revoke certificate** (on its page, needs `pki:revoke`): pick a reason. It is done at once and cannot be undone:
  FreeRADIUS and the web console refuse the certificate from then on.
- **Sign a CSR, New key + certificate, Convert** are done at once: what they make is shown only on their result page.
- **PKI → ACME:** the machines enrolled for DNS-01, each with its page and **Withdraw** (waits for DNS' Apply on
  DNS → Zones); **Enroll** makes the machine's key, shown once, and BIND takes it at once.

## 4.5.2.3 Revoke any certificate from the console

Design: [1.5.1.9](../volume_1_description_and_architecture/1.5.1-pki-chain.md#1519-any-certificate-revoked-from-the-console-0100); decision 2.1.5.13.
Needs `pki:read` to see the list and `pki:revoke` to revoke.

1. Open **PKI → Certificates → Issued**. Each row says where the certificate came from: **issued here**, **fabric's
   own** (the services using it), **ACME** (a LAN machine), **802.1X** (the device and its roles) or **Step-CA** (signed
   by another provisioner). Use the filter above the list to show one source alone.
2. Select **Revoke** in the certificate's row. Its page opens at the Revoke form.
3. Pick the reason, and type the certificate's name again (shown as *Type `name` to confirm*; its serial when it has
   no name).
4. Select **Revoke certificate**. It is done at once and cannot be undone: it is in the CRL from then on, and
   FreeRADIUS, nginx's client checks and the web console refuse it.

For one of **fabric's own** certificates, the page says a new one is issued first: fabric issues and installs it, the
services using it reload or restart, and only then is the old one revoked. If the new one cannot be issued, nothing is
revoked and the page says why.

## 4.5.2.4 Revoke a certificate not listed

For a certificate the list does not hold (one copied off a machine, or one Step-CA's database could not be read
for), on **PKI → Certificates → Issued**:

1. Under **Revoke a certificate not listed**, give its serial (with or without colons), or paste or upload the
   certificate itself.
2. Select **Find it**. fabric checks that this install's CA signed it and shows its page.
3. Revoke it as 4.5.2.3 steps 3–4 say.

Refused, saying why, nothing revoked: a serial that is not hexadecimal, text that is not a certificate, the CA's own
root or intermediate, a certificate this CA did not sign, a serial this CA never signed, one already revoked.

## 4.5.2.5 Set certificate lifetimes and renewal

Design: [1.5.1.10](../volume_1_description_and_architecture/1.5.1-pki-chain.md#15110-lifetimes-and-renewal-set-in-the-console-0100); decision 2.1.5.14.
Needs `pki:read` to see the page and `pki:settings` to change it (in `fabric-pki-operator`). From the command line:
[4.5.1.8](4.5.1-certificates.md#4518-certificate-lifetimes-from-the-command-line).

1. Open **PKI → Lifetimes**. It shows fabric's own certificates' lifetime and **renew at** with each one's next
   renewal, the ACME lifetime with the client setting that matches it (certbot's `renew_before_expiry`), the
   hand-issued default and maximum, how many 802.1X machine certificates expire within 30 days, and the limits
   (the intermediate CA's days left).
2. Change the values, in days, and select **Save the lifetimes**. The change waits for PKI's **Apply** in the top bar; Review
   shows it.
3. Select **Apply**. fabric saves the values, updates Step-CA (restarting it when its configuration changed), and
   renews at once fabric's own certificates the new values say are due. Certificates already issued keep their
   expiry until they are renewed; a LAN machine's next ACME certificate takes the new lifetime.
4. On each LAN machine using ACME, set its client's renewal to match (the page shows the setting).

Refused, saying why, nothing changed: a lifetime longer than the intermediate CA has left; fabric's own lifetime under
2 days; **renew at** under 1 day, or less than 1 day before the lifetime's end; a hand-issued default over its maximum;
a value that is not a whole number of days. A server certificate over 398 days, or renewal under 7 days before the
end, is allowed with a note.

## 4.5.2.6 Troubleshoot the Issued list and Lifetimes

| Symptom | Cause | Fix |
|---|---|---|
| Issued says *Step-CA's own certificates (ACME, and any it signed itself) are not listed* | Step-CA is not running, or its image predates 0.10.0 (no `fabric-certlist`) | `sudo fabricctl status`; start Step-CA, or upgrade (Volume 3) so its image is built again. The rest of the list is right; revoke a missing one by serial (4.5.2.4) |
| Issued says *fabric's own certificates are not listed: the setting hostname_… is missing* | The settings were never rendered by a setup run | `sudo fabricctl setup` |
| 802.1X rows show a device with no roles | The directory could not be read | Check the domain controller (`sudo fabricctl status`); the rows keep the device's name |
| Revoking one of fabric's own says *a new certificate for … could not be issued, so nothing was revoked* | Step-CA cannot sign (down, or its provisioner key unreadable) | Fix Step-CA, then revoke again; the old certificate stays in use until then |
| A Lifetimes value is refused as *longer than the intermediate CA has left* | The intermediate expires sooner than the lifetime | Choose a shorter lifetime; the intermediate's own renewal is 1.5.1.6 |
| Lifetimes shows *refused as set now* | A value set earlier is now over a limit (the intermediate has aged) | Nothing breaks; set a shorter value when convenient |
| After Apply, *the lifetimes are saved, but Step-CA did not restart* (or is not healthy) | Step-CA failed to start with its new configuration | `journalctl -u stepca`; `sudo fabricctl doctor` |
