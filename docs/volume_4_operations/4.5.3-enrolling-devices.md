## 4.5.3.1 Before you start

- You need the permission `pki:enrol` (the admin, PKI operator and equipment operator bundles have it).
- For the device to join the network with its certificate, it needs a **device** in the directory, enabled, in a role
  with `network:eap-tls` (web console: Directory → Devices; [4.11.1](4.11.1-radius.md)), and your switch or access
  point using fabric's FreeRADIUS. Make the device first, then choose it when you enrol: the certificate is linked to
  it as it is issued.
- Have the Wi-Fi network's name (SSID) at hand, exactly as the access point broadcasts it.
- Each file is for **one** device. Make a new one for each phone or laptop.

## 4.5.3.2 An iPhone or iPad

1. On the iPhone, open the web console (`https://<console name>`), sign in, and go to **Step-CA → Enrol a device**.
   (On a computer works too: then AirDrop or mail the file to the iPhone.)
2. Under **iPhone, iPad or Mac**: type a name for it (letters, digits and dashes, e.g. `alice-iphone`), choose its
   device, type the Wi-Fi name, and press **Download the profile**. The profile can be used **once**, within the
   minutes shown (`scep_challenge_minutes`, 60 by default).
3. Safari asks to download a configuration profile: allow it. Open **Settings → Profile Downloaded** (or Settings →
   General → VPN & Device Management), tap the profile, **Install**, enter the phone's passcode, and **Install** again.
   It shows as "Not Verified": fabric does not sign profiles yet.
4. The phone makes its key, fetches its certificate from fabric, and joins the Wi-Fi network on its own. In the
   console the certificate now appears under **Issued by enrolment**, linked to the device.

To remove it from the phone: Settings → General → VPN & Device Management → the profile → **Remove Profile**. That
removes the certificate, the Wi-Fi settings and fabric's root CA from the phone; revoke the certificate too (4.5.3.5).

## 4.5.3.3 A Mac

As for an iPhone (4.5.3.2), from the Mac: tick **Also wired 802.1X (Mac)** when the Mac uses a network cable on a
switch port with 802.1X. Open the downloaded `.mobileconfig`; macOS says the profile needs review: open **System
Settings → Privacy & Security → Profiles** (or **General → Device Management**), double-click it, **Install**, and
enter an administrator's password.

## 4.5.3.4 An Android phone

1. In the web console, **Step-CA → Enrol a device**, under **Android and other devices**: type a name, choose its
   device, and press **Make the file**. Tick **For Android 11 and older** only for such a phone: it uses an older
   cipher (the form says so), which newer phones do not need.
2. The result page shows the **password once**: copy it now. It is not stored anywhere and cannot be shown again.
   Download `<name>.p12` and send it to the phone over a channel you trust (a cable, or a share only you can open).
3. On the phone: **Settings → Security (and privacy) → More security settings → Encryption & credentials → Install a
   certificate → Wi-Fi certificate** (the names vary by maker), pick the `.p12`, enter the password, and give it a
   name.
4. Add the Wi-Fi network: **EAP method** TLS; **CA certificate**: fabric's root (install `root-ca.crt` from
   `http://ca.<domain>/certs/` first as a CA certificate, or choose "Use system certificates" only if fabric's root is
   installed); **Domain**: the RADIUS server's name (`radius.<domain>`); **User certificate**: the one you just
   installed; **Identity**: the name you gave. Connect.

Delete the `.p12` from wherever you copied it once it is installed.

## 4.5.3.5 Withdrawing, revoking and enrolling again

- **A profile not yet used** is listed under **Open profiles** until it is used or expires. **Withdraw** it if it went
  to the wrong place: nothing can be enrolled with it after that. Only the person who made it, or someone with
  `pki:revoke`, can withdraw it.
- **A lost or replaced device:** under **Issued by enrolment**, **Revoke** its certificate (`pki:revoke`). FreeRADIUS
  refuses it at its next sign-in, linked or not ([4.5.1.5](4.5.1-certificates.md#4515-revoking-a-certificate)).
- **A certificate about to expire** (`scep_cert_days`, a year by default; warned 30 days ahead on the Overview): enrol
  the device again with a new profile or file, then revoke the old certificate.

## 4.5.3.6 When it does not work

| What you see | Why, and what to do |
|---|---|
| The iPhone says the profile "could not be installed" or the SCEP request failed | The challenge was already used, expired or withdrawn: make a new profile. The audit (`SCEP_CHALLENGE_REFUSED`) says which. |
| The audit says the request's name is not the profile's | The profile was edited, or its challenge was copied into another request: make a new profile. |
| Nothing in the audit at all | Step-CA could not reach fabric's hook: check that the web console runs (`fabricctl status`) and `systemctl status fabric-scep-hook`. |
| The certificate is listed with "not linked" | The directory refused the link (the device was removed, or the DC was down): link it by hand (Step-CA → Issued, or the device's page) or enrol again. |
| Android says the password is wrong although it is right | An Android 11 or older phone: make a new file with **For Android 11 and older** ticked. |
| The device has its certificate but does not join | The device is disabled, has no `network:eap-tls`, or the Wi-Fi name is different: see the FreeRADIUS tab's recent decisions ([4.11.1](4.11.1-radius.md)). |
