## 4.10.1.1 DHCP (optional: Kea)
Off unless turned on later in the settings (`sudo fabricctl`, then applied) or with `install_kea: true` and its `dhcp` settings
in a vars file (2.1.2.16).
**A preview in 0.7.0** ([1.10.3.9](../volume_1_description_and_architecture/1.10.3-serving-networks.md#11039-a-preview-in-070)): it works as described here, but
0.8.0 finishes it and may change it; setup's plan and the Kea tab say so.
**Kea 3.0 LTS**, from ISC's signed apt repository (key pinned by
fingerprint, exact package version in `images.lock.yaml`), built locally on
fabric's pinned Debian image. One DHCP server per LAN: switch off your
router's DHCP first.

```yaml
install_kea: true
dhcp:
  interfaces: [eth0]
  lease_time: 86400                       # seconds, 300 to 2592000
  # ddns: false                           # don't register hostnames in DNS
  # ddns_subdomain: dhcp                  # -> <name>.dhcp.<domain>
  # dns: [192.168.4.2]                    # DNS servers handed out (default: this host)
  options:                                # any DHCP option, every subnet (Kea's names, or code: 1-254)
    - { name: time-offset, data: "-18000" }
  option_defs:                            # options Kea has no name for
    - { name: ztp-url, code: 239, type: string }
  client_classes:                         # clients matched by a Kea expression get their own settings
    - name: pxe-uefi
      test: "option[93].hex == 0x0007"
      next_server: 192.168.4.30
      boot_file_name: ipxe.efi
      options: [ { name: tftp-server-name, data: 192.168.4.30 } ]
  subnets:
    - subnet: 192.168.4.0/22
      name: main                          # one word, unique
      vlan: 1                             # a record of what the network is for: fabric configures no switch
      notes: "the house LAN"
      pools: ["192.168.5.100 - 192.168.5.200"]
      routers: 192.168.4.1
      options: [ { name: ntp-servers, data: 192.168.4.2 } ]          # this subnet only
      reservations:
        - { mac: "aa:bb:cc:dd:ee:ff", ip: 192.168.4.20, hostname: printer,
            options: [ { name: boot-file-name, data: printer.bin } ] }   # this client only
```

An option is `{name | code, data, space, csv_format, always_send}` — Kea's own option-data. The most
specific level wins (reservation, class, subnet, every subnet), and an option named like one fabric sets
itself (`domain-name-servers`, `ntp-servers`, `domain-name`, `domain-search`, a subnet's `routers`) replaces
fabric's; `fabricctl dhcp status` and the Kea tab list such replacements.

Every subnet keeps an `id` (Kea ties leases to it): fabric stores it on the first change, so removing one
subnet never moves another's leases.

Setup refuses (before changing anything) a pool outside its subnet or overlapping another pool, a
reservation inside a pool or outside every subnet, duplicate MACs or addresses, a name or VLAN used twice,
a malformed option, and a static A record inside a pool (Kea would hand it out). Then **Kea itself checks
every changed configuration** (`kea-dhcp4 -t` in fabric's Kea image) before it is installed: an option Kea
does not know, data that does not fit it or a client-class expression it cannot parse is refused with
Kea's message, and nothing is changed.

**Hostnames in DNS.** Clients that send a hostname are registered as
`<name>.dhcp.<domain>`: a zone of its own, delegated from `<domain>`, that
fabric creates once and never re-renders (apply would wipe the dynamic
names otherwise). Kea's DDNS key (`kea-ddns`, in OpenBao) may change only
A, AAAA and DHCID records in that zone — nothing in `<domain>` itself — and
a client cannot take over another client's name (`check-with-dhcid`).
Reverse (PTR) records for DHCP clients are not registered yet.

Day to day (the Kea tab of the web UI does the same):

DHCP can be turned on and off from the Kea tab or with `fabricctl dhcp on|off` (1.10.3.5). Each DHCP change also brings the host firewall in line: making it is your yes to the rules it implies (67/udp on the served interface; the subnet's clients let in to fabric's DNS, time, pages and the domain's ports; DNS and time only for a guest subnet).

```bash
sudo fabricctl dhcp on --interface eth1 --subnet 10.20.0.0/24 --pool "10.20.0.100 - 10.20.0.199"   # the first time
sudo fabricctl dhcp on                                  # again later: what it served before
sudo fabricctl dhcp off                                 # Kea stops; settings and leases kept
sudo fabricctl dhcp status                              # subnets (name, VLAN, notes), pools, options, classes
sudo fabricctl dhcp leases                              # active leases, from Kea
sudo fabricctl dhcp reserve aa:bb:cc:dd:ee:ff 192.168.4.20 printer
sudo fabricctl dhcp unreserve aa:bb:cc:dd:ee:ff
sudo fabricctl dhcp add-subnet 192.168.20.0/24 --name iot --vlan 20 --router 192.168.20.1      --pool "192.168.20.100 - 192.168.20.200" --notes "IoT: internet only"
sudo fabricctl dhcp set-subnet iot --notes "trunked on switch1 port 24" --add-pool "192.168.20.50 - 192.168.20.60"
sudo fabricctl dhcp remove-subnet iot                    # refused while it has active leases (--force)
sudo fabricctl dhcp option set tftp-server-name 192.168.4.30 --class pxe-uefi
sudo fabricctl dhcp option set 66 192.168.4.30 --subnet iot     # by code
sudo fabricctl dhcp option unset 66 --subnet iot
sudo fabricctl dhcp class add pxe-uefi --test "option[93].hex == 0x0007" --next-server 192.168.4.30 --boot-file ipxe.efi
sudo fabricctl dhcp class remove pxe-uefi
```

Every change is saved to `vars.yaml` and applied at once (`--no-apply` to
batch); for a reservation the client gets the address at its next renewal. Leases live in
`/opt/kea/leases` (memfile) and survive restarts and upgrades. The firewall
opens UDP 67 on the DHCP interfaces only.
