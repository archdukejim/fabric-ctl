## 4.10.2.1 What it is, and where 0.9.0's port stands

From 0.9.0 every site's VLANs, subnets, ranges and addresses are one plan, kept in the domain (design:
[1.10.4](../volume_1_description_and_architecture/1.10.4-address-manager.md)). Kea and the site's static names
are rendered from it at every apply.

0.9.0 is ported onto 0.8.0's directory area by area (1.10.4.41), and this chapter grows with it:

- **Ported:** the commands below, which write the plan.
- **Still to come:** rendering Kea and DNS from the plan, moving a site's `dhcp.subnets` into it at the upgrade, the
  DHCP options, the scans and the console's Networks tab.
- **Until then:** Kea keeps serving `vars.yaml`'s subnets, and a change made here waits in the domain for that
  rendering.

You run every command as root on a fabric host. Root acts for the Enterprise Admin, so it may change any site's
plan. Who else may change a plan is set by the grants' networks rights (4.6.10.8). A change to a plan never needs an
apply of another site.

## 4.10.2.2 Seeing the plan

```bash
sudo fabricctl ipam show                 # this site: its number, each VLAN, its subnet and ranges, every address
sudo fabricctl ipam show house2          # another site's plan
sudo fabricctl ipam find 10.1.20.37      # the address's row in any site, or its subnet and range if unrecorded
sudo fabricctl ipam find cam1            # an address or a VLAN by name
sudo fabricctl ipam find aa:bb:cc:dd:ee:ff
sudo fabricctl ipam export > plan.csv    # every site's address table (export <site> for one)
```

`show` lists this site's live leases beside the addresses: a lease on an address nobody recorded has the kind
`lease`.

The CSV's columns are: site, VLAN, VLAN name, subnet, address, kind, range, name, MAC, owner, DNS, lease and notes.
A cell a spreadsheet would read as a formula is written with a leading apostrophe.

## 4.10.2.3 VLANs and their subnets

```bash
sudo fabricctl ipam vlan add 20 --name iot --purpose "cameras and sensors"     # 10.<site>.20.0/24, split suggested
sudo fabricctl ipam vlan add 30 --name guest --subnet 192.168.30.0/24 --access guest
sudo fabricctl ipam vlan add 300 --name lab --subnet 10.1.64.0/22 --gateway 10.1.64.1 --no-split
sudo fabricctl ipam vlan add 40 --name printers --no-subnet                   # a record only
sudo fabricctl ipam vlan set 20 --notes "trunked on switch1 port 24" --dhcp off
sudo fabricctl ipam vlan remove 40
```

- **The suggested subnet:** without `--subnet`, a VLAN from 1 to 255 is given `10.<site number>.<VLAN>.0/24`, split
  as:
  - gateway `.1`;
  - static `.2-.99`;
  - DHCP `.100-.249`;
  - reserved `.250-.254`.

  `--no-split` leaves out the ranges. A site without a number is given its suggested one, and the command says which.
- **Overlaps:** `--allow-overlap "<why>"` lets a subnet overlap another site's network, for two networks that are
  never routed together (NAT, separate paths).
- **The relay:** `--relay IP` is needed only when the relay's address lies outside the subnet (1.10.3.2).
- **Removing:** `vlan remove` refuses while the subnet records addresses. `--force` removes them with it.

## 4.10.2.4 Ranges

```bash
sudo fabricctl ipam range add 20 dhcp 10.1.20.100 10.1.20.199
sudo fabricctl ipam range add 20 reserved 10.1.20.250 10.1.20.254 --notes "spare for the new switch"
sudo fabricctl ipam range remove 20 10.1.20.100          # by its first address
```

Ranges never overlap. A `dhcp` range is Kea's pool and may hold only reservations, so a `dhcp` range over a static
address or over the gateway is refused.

## 4.10.2.5 Addresses

```bash
sudo fabricctl ipam address add 10.1.20.10 --kind static --name nas --owner office --dns on   # nas.<domain> + PTR
sudo fabricctl ipam address add 10.1.20.150 --kind reservation --mac aa:bb:cc:dd:ee:ff --name cam1
sudo fabricctl ipam address add 10.1.20.2 --kind infrastructure --name switch1 --dns on
sudo fabricctl ipam address set 10.1.20.10 --notes "backups at 02:00"
sudo fabricctl ipam address remove 10.1.20.150
```

- **One claim per address:** a second claim, or a claim on the gateway's address, is refused, naming the first.
- **Reservations:** a reservation needs the device's MAC and may lie inside a DHCP range.
- **Static addresses:** one outside the static ranges is warned about, never refused.
- **DNS:** `--dns on` records that the address's name is published as `<name>.<domain>` with its PTR, a
  reservation's too. Publishing comes with rendering from the plan (1.10.4.41, area 5).

## 4.10.2.6 Another site's plan

`--site <site>` on any change writes to that site's plan.

```bash
sudo fabricctl ipam vlan add 10 --name mgmt --site house2
sudo fabricctl ipam address add 10.2.10.5 --kind static --name nas --site house2
```

- **Who may do it:** root may change any site's plan. Anyone else needs a grant with the networks right `plan` at
  that site, or at `all` (4.6.10.8). The Directory Administrators may do it everywhere.
- **Where it is written:** this site's DC, or at a site with a read-only DC, the writable DC it replicates from. It
  reaches the other site by replication.
- **When it takes effect:** at that site's next rendering of its plan.

## 4.10.2.7 The gateway's DHCP relay

Each VLAN's gateway relays its DHCP to fabric (1.10.4.5).

- **On a UniFi gateway:** *Settings → Networks →* the VLAN's network *→ DHCP mode: DHCP Relay*, server: fabric's
  address (`host_ip`).
- **On other gateways:** the setting may be called a DHCP helper or a relay. Point it at the same address.

fabric opens 67/udp for the relay at the apply.

## 4.10.2.8 The site's number

The site's number is the second octet of every subnet fabric suggests, `10.<number>.<VLAN>.0/24` (2.1.10.12). Its
suggestion is the site's order in the domain. To see it or set it:

```bash
sudo fabricctl ipam block                  # this site's number, or "none (suggested n)"
sudo fabricctl ipam block 4                # set it: 1-255, no other site's
sudo fabricctl ipam block 3 --site house2  # another site's
```

Changing the number changes only what fabric suggests from then on: subnets already in the plan keep their
networks, and nothing is applied. A number another site has is refused, naming that site. Setup's question for it
comes with the setup area (1.10.4.41, area 8).

## 4.10.2.9 More than one subnet on a VLAN

A VLAN may have more than one subnet, for example a second network while renumbering (2.1.10.18):

```bash
sudo fabricctl ipam subnet add 20 10.1.21.0/24 --notes "renumbering"   # named iot-2 (after VLAN 20, iot)
sudo fabricctl ipam subnet add 40 10.1.40.0/24                         # a first subnet for a VLAN kept as a record
sudo fabricctl ipam subnet set iot-2 --dhcp off                        # by name, or by network
sudo fabricctl ipam subnet remove 10.1.21.0/24 --force                 # with its ranges and addresses
```

- **Options:** `subnet add` takes the same options as `vlan add` (`--name`, `--gateway`, `--dhcp`, `--relay`,
  `--no-split`, `--allow-overlap`). Every rule still holds: no overlap without a reason, and one claim per address.
- **On a VLAN with several subnets:**
  - `vlan set`'s subnet options (`--gateway`, `--dhcp`, `--relay`, `--allow-overlap`) are refused: change each
    subnet with `subnet set`.
  - `range add 20 …` and `address add … --vlan 20` go to the VLAN's subnet that holds the address.
- **Removing:** `subnet remove` refuses while the subnet records addresses, unless you give `--force`. The VLAN
  stays.
