## 4.6.4.1 The layers

Settings → Sign-in security lists first the security relaxations that are on, on this page and on the setup wizard's
(2.1.8.20): each stays listed until it is put back.

A new install asks everyone for a username and password (2.1.6.23); the domain logon signs people in on joined
computers. Three layers can be raised:

| Layer | Values (weakest first) | What it covers |
|---|---|---|
| `admin-2fa` | none, any, totp, passkey | The admin tools: the web console, OpenBao's UI. Never less than `everyone-2fa` |
| `everyone-2fa` | none, any, totp, passkey | Every sign-in, every app added with `fabricctl sso` |
| `client-cert` | off, on | The web console asks for a client certificate from fabric's CA |

`any` lets a person with a passkey use it and everyone else an authenticator app (TOTP); `passkey` means Windows
Hello, a phone or a security key, unlocked with its PIN, fingerprint or face. `sudo fabricctl security` shows them all;
so does the web console's **Security** tab. While the admin tools ask for a password only, status and the Overview
list it as a relaxation.

## 4.6.4.2 Raising a layer

In the web console: **Security**, pick the stronger value, **Raise** (admins only; a sign-in from the last 5 minutes is
asked for first). Keycloak and the web console use it at once; people enrol the new factor at their next sign-in. From
the host: `sudo fabricctl security raise <layer> [<value>]`.

Before turning `client-cert` on, give each admin a certificate (`sudo fabricctl client-cert <user>`), import yours,
and open the Security page again: it is refused while your browser does not present your own certificate.

## 4.6.4.3 Lowering a layer

Only on the fabric host:

```bash
sudo fabricctl security lower admin-2fa
```

It says what is lost and asks you to type the layer's name back (`--yes` does not skip it; it refuses without a
terminal). The lowering is in the audit log, and `fabricctl doctor`, `fabricctl status` and the web console's Overview
show it until the layer is raised back to what it had. Setup never lowers a layer: a settings file that would is
refused.

## 4.6.4.4 Signing in with the domain logon

Off by default since 0.6.4, not asked at setup (2.1.6.32, 2.1.2.16; installs from before keep theirs): turn it on here. When on, the site's DC holds `fabric-sso-<site>` and Keycloak accepts Kerberos tickets; fabric's Windows baseline
GPO and the Linux join script tell browsers to use them for `sso.<domain>`. A second factor, when raised, is still
asked after it. Turn it off or on in **Directory → Kerberos** (4.6.11.15) or with `sudo fabricctl security kerberos off|on`.
