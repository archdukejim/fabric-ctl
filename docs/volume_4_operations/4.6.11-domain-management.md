The commands below run as root on a fabric host (root acts for the Enterprise Admin). The same actions are
fabric-agent's routes, for the console's Directory pages (1.3.3); they refuse what the commands refuse. Design:
[1.6.12.17](../volume_1_description_and_architecture/1.6.12-domain-management.md#161217-what-d4-built-080).

## 4.6.11.1 Who may do what

- **Root on a fabric host, or fabric-admin:** everything below, the Directory Administrators' group included.
- **A Directory Administrator:** everything except the Directory Administrators themselves and their group's members.
- **Anyone else:** what a grant gives them (people `edit`, `reset`, `unlock`, `disable`, `add`; machines `add`,
  `move`, `disable`, `remove`, `groups`) on the people and machines that grant's where holds (4.6.10), and the members
  of the groups they manage, within the controls set for them. The refusal says which right is missing, and where.
- **Nobody, through fabric:** `fabric-admin` and AD's top tier (reset its password with `sudo fabricctl admin
  reset-break-glass`, 4.6.9), fabric's own accounts, the DCs and the fabric hosts.

## 4.6.11.2 A person: edit, unlock, disable, enable

```bash
sudo fabricctl domain person edit bob --name "Bob Builder" --email bob@example.org
sudo fabricctl domain person edit bob --title "Site engineer" --department Operations --phone "+44 20 7946 0000" \n    --city Leeds --country GB --manager carol --employee-id E-1001
sudo fabricctl domain person edit bob --phone ""     # an empty value clears a field (never the names)
sudo fabricctl domain person unlock bob          # a lockout cleared; the password kept
sudo fabricctl domain person disable bob         # every sign-in blocked at once, sessions ended
sudo fabricctl domain person enable bob
```

A person's fields are AD's standard attributes (2.1.6.93): `--first`, `--last`, `--name` (display name), `--email`,
`--phone`, `--mobile`, `--title`, `--department`, `--company`, `--office`, `--city`, `--state`, `--country` (two
letters), `--manager` (a person's user name) and `--employee-id`; the route `POST /v1/people/<uid>/edit` takes the
same names (`employee_id`). Reset, add and remove stay `fabricctl people` (4.6.1). An e-mail address that another
person has is refused, and so is a manager who is not a person.

## 4.6.11.3 Groups and their managers

```bash
sudo fabricctl domain group list                         # every group and its kind
sudo fabricctl domain group create ops-team --description "the ops team"
sudo fabricctl domain group scope ops-team               # what it grants, its managers, its members
sudo fabricctl domain group managers ops-team --set sup --add on --remove off --only-from site-lan
sudo fabricctl domain group members ops-team add bob     # a person or a group
sudo fabricctl domain group delete ops-team              # refused while in use, naming where
```

A group's managers (people, or groups whose members all manage it) change its members and nothing else: here sup may
add people already in `site-lan`, and may not remove anyone. Only a Directory Administrator sets a group's managers
(for `directory-admins`, only root or fabric-admin). fabric's own groups, AD's, the grants' computed groups and the
`machines-*` groups are refused, with why.

## 4.6.11.4 OUs

An OU is named by its path, top down. Your own OUs go under `people`, `service-accounts`, `groups` and
`machines/servers`, `machines/desktops` and `machines/network`. OUs grant nothing: access is by groups and grants.

```bash
sudo fabricctl domain ou list                            # fabric's marked; what each holds
sudo fabricctl domain ou create machines/servers web
sudo fabricctl domain ou rename machines/servers/web www
sudo fabricctl domain ou delete machines/servers/www     # refused while it holds anything, naming what
```

fabric's agent has no rights under `OU=service-accounts` yet, so an OU there is refused by AD, saying so.

## 4.6.11.5 Computers: folder, type, sites

```bash
sudo fabricctl domain machine move srv1 machines/servers/web   # any folder under machines; nobody's access changes
sudo fabricctl domain machine type dsk1 server --move          # its type group, and its type's folder
sudo fabricctl domain machine sites srv1 add lan               # or remove
```

A type change is compiled into the grants at once: the machine gets its new type's sign-in rules at the next sign-in.
A machine in one of your own folders stays there with `--move`, and the command says so.

## 4.6.11.6 A keytab for a service on a machine

The console never holds a key. Ask for the command, then give it to the machine's administrator:

```bash
sudo fabricctl domain machine keytab srv1 --service HTTP --user www-data
#   sudo fabric-keytab --machine srv1 --service HTTP --user www-data
```

They run that line in an SSH session on srv1 (joined with fabric's `join-linux.sh`, 4.6.6, which installs
`fabric-keytab`). It adds `HTTP/srv1.<domain>` and `HTTP/SRV1` to srv1's own computer account and writes
`/etc/krb5-http.keytab` (or `--path`), owned by `www-data`, mode 0600. Running it again gives the same keytab. It
refuses another machine's name, the machine's own service classes (`host`, `cifs`), a user the machine does not
have, and `/etc/krb5.keytab` as the path. A name already on another account is refused by the DC: see the duplicates
in 4.6.11.7.

## 4.6.11.7 Kerberos: the realm, service principals, the ticket policy

```bash
sudo fabricctl domain kerberos show              # realm, KDCs, the ticket policy, domain-logon sign-in
sudo fabricctl domain kerberos spns              # every service principal; DUPLICATE marks a broken one
sudo fabricctl domain kerberos policy --ticket-hours 8 --renew-days 5 --skew-minutes 5
```

The policy is applied at once (the DC restarts; `--no-apply` only records it, for the next `sudo fabricctl
--apply`). It is refused, with why, unless a ticket lasts at least 1 hour and no longer than its renewal, a renewal
lasts 1 to 30 days, and the clock skew is 1 to 15 minutes. It is the `ad_kerberos_policy` setting, so a settings
file can carry it too. A duplicate SPN breaks Kerberos for both accounts: remove it from the one that should not have
it (`samba-tool spn delete <spn> <account>` on the DC's host).

## 4.6.11.8 Changing your own password

Every person changes their own password from the console's My account (with the console's next pages): the current
password, then the new one. It is changed in the domain at once, checked against the domain's policy; their other
signed-in sessions end, the one they used stays. A wrong current password, or one the policy refuses, changes
nothing and says why. There is no command for it: root is no person.
