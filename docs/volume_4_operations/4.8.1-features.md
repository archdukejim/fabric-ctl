# 4.8.1 Pages and features

Topics:
- 4.8.1.1 Features

## 4.8.1.1 Features

The console has a bar along the top and a navigation down the left. The top bar shows the install's host and
domain, the fabricctl version, and your name: its menu has **Sign out** (and, from 0.8.0's next steps, **My
account**). The navigation has one entry per part of fabric, its pages listed below the entry you are in; the page
shown is highlighted. You see only the entries, pages and forms your permissions allow (see [Who may do
what](../volume_1_description_and_architecture/1.8.2-webui-security.md#18211-who-may-do-what)): an entry appears when
you may see one of its pages. On a phone (under 768 px wide) the navigation folds behind the **Menu** button and each list
becomes a stack of cards, one per row, each value under its column's name; nothing scrolls sideways. A
status light always says what it means (hover it, or a screen reader reads it). Nothing needs JavaScript.

After a change, the page you return to says what was done, or why it was refused, once.

Pages marked *optional* belong to services that can be added or removed on a running install (DHCP, 802.1X). An old
address (`/bind9`, `/stepca`, `/openbao`, `/freeradius`, `/security`, `/directory?view=…`) still works: it takes you
to the page's new address.

| Entry · page (address) | What it does |
|-----|--------------|
| Overview · Health (`/`) | One status light per installed service (`nginx`, `bind9`, `stepca`, `samba`, `postgres`, `keycloak`, `openbao`, `kea`, `freeradius`, `fluentbit`, `fabric-web`, `fabric-agent`; a service that is not installed is left out). Green: running (and its Docker health check passes, where it has one). Amber: starting. Red: stopped or health check failing, with the reason beside it. Also "N of M services healthy". Needs `status:read` |
| DNS · Zones (`/dns/zones?zone=<key>`) | Zone picker; records (A, AAAA, CNAME, MX, TXT, SRV) with each A/AAAA record's automatic PTR (or why it has none); add or delete a record in `vars.yaml`; Apply |
| DNS · Zones · Reverse zones (`/dns/zones?view=reverse`) | Read-only: the reverse zones and PTR records generated from the forward A/AAAA records (see [Reverse DNS](4.4.5-reverse-dns.md#4451-reverse-dns)), hand-written reverse zones, and addresses that get no PTR, with the reason |
| DNS · Zones · TSIG keys (`/dns/zones?view=tsig`) | Keys with their effective update rights and ACLs (never secrets). **New TSIG key for a zone**: a forward zone and one scope — certbot DNS-01 for listed hosts, certbot DNS-01 for any host in the zone, or any name with chosen record types; generated secret or an existing one kept. The secret and the `rfc2136.ini` (download) are shown once. **New secret** (rotate) and **Delete**. Apply publishes. ACLs and update policies: placeholder (`fabricctl acl`) |
| DHCP · Kea (`/kea`) *optional* | Subnets (pools, router, reservation count), reservations with **Remove**, **Reserve** (MAC, address, hostname; saved and applied at once), and live leases from Kea. When DHCP is off: how to turn it on. Needs `dhcp:read`; changes need `dhcp:write`. See [DHCP](4.10.1-dhcp.md#41011-dhcp-optional-kea) |
| PKI · Certificates (`/pki?view=…`) | Sub-menu: **Certificate authority** (root + intermediate subject, expiry, SHA-256; link to `info.<domain>/certs/`), **Sign a CSR** (upload or paste PEM/DER → review names, key, policy → sign), **New key + certificate** (for devices that cannot make a CSR: RSA-2048/3072/4096 or EC P-256/P-384), **Inspect** (decode a certificate, chain or CSR; says whether this fabric issued it), **Convert** (PEM `.crt`, DER `.cer`, full chain `.pem`/`.p7b`, and with its key a `.p12`), **Issued** (every certificate issued by hand, with expiry status). See [Manual certificates](4.5.2-manual-certificates.md#4521-manual-certificates) |
| Directory (`/directory`, `/directory/people`, `/directory/domain`, `/directory/machines`, `/directory/gpo`) | **Overview**: the domain, its level and controllers, the roles, replication, the sites and the counts. **People**: the site's people (state, name, user name, e-mail, last sign-in), searched and paged; each person's page with their details, groups, certificates and devices and **Reset password**, **Unlock**, **Disable**/**Enable**, **Edit details**, groups and **Remove person**; **Add person** (see [4.6.11.9](4.6.11-domain-management.md#46119-in-the-console-the-overview-and-people)). **Domain**: the domain, its controller and the password policy. **Machines**: the domain's computers, host groups and sudo rules. **Group Policy**: what is set, and a search to set a policy. Needs `people:read` or `domain:read` |
| 802.1X · Devices and Device roles (`/8021x/devices`, `/8021x/roles`) | **Devices**: list (status light, type, MACs, owner, roles, effective access), add, and a page per device (`/8021x/devices/<name>`) to edit it, see what its roles add up to, manage its linked certificates (issue one or sign its CSR, with `pki:issue` / `pki:sign`; unlink), delete. **Device roles**: what member devices may do (permissions, optional VLAN, priority), add/edit/delete (refused while devices are in it). Needs `devices:read`. See [Device access (RBAC)](4.8.2-device-access.md#4821-device-access-rbac) |
| 802.1X · RADIUS clients, Recent decisions, Setup guides (`/8021x`, `/8021x/decisions`, `/8021x/guides`) *optional* | The server (host IP, the certificate name supplicants check), RADIUS clients (address, whether Message-Authenticator is required) with **New secret** and **Remove**, **Add client** (a generated secret or one the device already has; shown once), **People**: the directory groups whose members may join by password (EAP-TTLS), with their VLAN and priority, **Map group** and **Remove**, and, on **Recent decisions**, the recent decisions: accepted or refused, method (EAP-TLS / EAP-TTLS / MAB), device or person, VLAN, MAC, which switch asked, and why. **Setup guides**: **Connect a switch** (the RADIUS settings filled in for this install, per-port modes, what must stay open, UniFi step by step) and **Connect Windows** (EAP-TLS for fabric's PCs and EAP-TTLS for shared PCs, each with a generated PowerShell script to download: Wired AutoConfig on, the fabric root CA trusted, the server pinned by name and CA, the device certificate imported, the 802.1X profile added; untested on Windows until the hardware test). Needs `radius:read`; changes need `radius:admin`. When 802.1X is off: how to turn it on. See [802.1X](4.11.1-radius.md#41111-8021x-optional-freeradius) |
| Secrets (`/secrets`, `/secrets/unlock`, `/secrets/disk`) | **Status**: state light (unsealed / sealed / not initialised / unreachable), version, seal, storage, where fabric's secrets live (OpenBao entry version and date), link to `vault.<domain>`, secret engines and sign-in methods (read as `fabric-agent`; no secret values). **Unlock methods**: every key slot (key file, security keys, USB sticks, KMIP HSMs) with presence light, device, key version; kill-switch state; warnings (a key file next to device slots, a single device); add a security key / USB stick / HSM (plugged-in tokens and USB disks are listed from the host), rotate the vault key, test or remove a method — all confirmed by typing the host name, and all need a sign-in from the last 5 minutes (otherwise you are sent to sign in again, then repeat the change). Security keys (PKCS#11 tokens, listed with their PIN state) are tested with SoftHSM2 only and HSMs (KMIP) with the PyKMIP server only; hardware tokens and vendor HSMs are untested. The dev preview runs every flow in memory. **Disk encryption**: a manual guide for LUKS with the same YubiKey (FIDO2) or USB stick (untested with hardware). **Secrets**: state of fabric's own secrets (`fabric/secrets` version and date; never values), a link to OpenBao's own UI (sign in with Keycloak) for `apps/`, and the break-glass commands |
| Overview · Doctor and Updates (`/overview/doctor`, `/overview/updates`) | **Doctor** runs fabric's checks as a job and shows each with its result; **Updates** lists each image with its version and **Update** or **Roll back** (with `images:update`). Needs `status:read` |
| DNS · DNS filter (`/dns-filter`) | The DNS filter's statistics, lists, rules, client groups, query log and upstreams. Needs `dns:filter` (the query log alone: `dns:querylog`) |
| PKI · ACME (`/pki/acme`) | The ACME directory and the machines enrolled for DNS-01, with **Enroll** and **Withdraw**. Needs `pki:read` |
| Federation (`/federation`) | Sites and their DC type, replication with each neighbour, conflicts, limits, the plan. Needs `federation:read` |
| Settings · Sign-in security (`/settings/sign-in`) | Each sign-in layer and its raises (second factors, the console's client certificate); lowering is done on the host. Needs `security:raise` |
| Apply (button on DNS · Zones and after a TSIG change) | fabric-agent runs the same apply as `sudo fabricctl --apply` (`interactive.py --apply`) — the whole deployment, not only DNS; the output is shown. Needs `dns:write` |
| Settings · Setup wizard (`/settings`) | The setup wizard: setup's choices that can change later (optional parts, memory, passwords and sign-in, the DNS filter's upstreams), one plan and one apply; the settings file's Export and Import. Needs `settings:admin`; Apply a sign-in from the last 5 minutes. See [The setup wizard](4.8.3-setup-wizard.md#4831-finish-setting-up-or-reconfigure-in-the-console) |
| Overview · Audit log (`/audit`) | The last 200 lines of `/opt/fabric/archive/audit.log`, newest first: logins, denials, and every change from the web UI and the CLI. Needs `audit:read` |

DNS record and TSIG edits only change `vars.yaml`; nothing is published until **Apply**. DHCP reservations and 802.1X changes are saved and applied at once. Every edit of `vars.yaml` and every apply takes the vars lock (`/opt/fabric/config/.vars.lock`, shared with the CLI), so concurrent sessions do not interleave.
