# 4.6.9 The administrators: break glass

Topics:

- 4.6.9.4 Breaking glass on the DC's host

The domain's administrators are in tiers ([1.6.12.2](../volume_1_description_and_architecture/1.6.12-domain-management.md#16122-who-manages-what-and-what-stays-fabrics)):
`fabric-admin` is the Enterprise Admin, kept for break glass; everyday work is the Directory Administrators', you
first among them.

## 4.6.9.1 Keeping the break-glass password

Setup writes `fabric-admin`'s generated password once, to `~/fabric-admin/fabric-admin-password.txt` in the home of
the account that ran `sudo fabricctl setup` (readable by that account alone). fabric keeps it nowhere else.

1. Copy the password into your own safekeeping: a password manager, or a sealed envelope kept where your
   organisation keeps such things.
2. Delete the file on the host:

   ```bash
   rm ~/fabric-admin/fabric-admin-password.txt
   ```

3. Check that the reminder is gone: `sudo fabricctl doctor` no longer warns about it, and the console's top bar stops
   showing it at your next sign-in (Overview at once). The removal is audited (`BREAK_GLASS_FILE_REMOVED`).

Until the file is deleted, every administrator sees the reminder. Sign in as `fabric-admin` only to break glass.

## 4.6.9.2 The tiers' password policies

The domain's password policy is everyone's but the tiers above the Directory Administrators' reach (2.1.6.71). Their
own policies are set on the host only, as root, acting for the Enterprise Admin; the console and its Settings never
show them a way in.

```bash
sudo fabricctl domain password-policy --tier enterprise-admin                # show fabric-admin's
sudo fabricctl domain password-policy --tier enterprise-admin --lockout-threshold 5
sudo fabricctl domain password-policy --tier directory-admins --minimum-length 16
```

Each takes the options of the domain's policy (4.6.5) and applies at once (`--no-apply` to wait). fabric-admin's
lockout always ends by itself: `--lockout-minutes 0` (until an admin unlocks it) is refused. A change is audited
(`AD_TIER_PASSWORD_POLICY`).

## 4.6.9.3 Resetting the break-glass password

When `fabric-admin`'s password is lost, or you think someone else has seen it, replace it on the host of a writable
domain controller (a read-only DC's host refuses and names the writable one):

```bash
sudo fabricctl admin reset-break-glass
```

It sets a new generated password, unlocks the account, and writes the password to
`~/fabric-admin/fabric-admin-password.txt` in your home (the account you ran `sudo` from), the path said in its
output; the old password stops working at once. Keep it as in 4.6.9.1, then delete the file. The reset is audited
(`BREAK_GLASS_RESET`). If it says `fabric-admin` is disabled, fabric leaves that as it is: enabling it is an
Enterprise Admin's choice.

## 4.6.9.4 Breaking glass on the DC's host

Nobody from the domain signs in to a host that runs a domain controller, except `fabric-admin`. From a machine of the
domain, with its password from your safekeeping:

```bash
kinit fabric-admin
ssh fabric-admin@<the host's name in the AD domain>
sudo -i                     # asks fabric-admin's password
```

Its password over SSH is refused; sign in with the Kerberos ticket. Every use is the top tier's: afterwards, think of
resetting the password (4.6.9.3).

## 4.6.9.5 Approving a local administrator account

Every local account with root or administrator rights on the DC's host that OpenBao does not manage, the account you
ran setup with included, is reminded of in the console's top bar and Overview and in `sudo fabricctl doctor` until it
is removed or approved. List them:

```bash
sudo fabricctl host accounts list
```

Each line says why the account is one (uid 0, a member of `sudo`, `wheel` or `admin`, a sudoers rule granting ALL)
and whether it is approved. Ideally remove the account (`sudo deluser <name>`, or take it out of the group or rule)
once you no longer need it. To keep it as a break-glass way in, approve it, for the Enterprise Admin:

```bash
sudo fabricctl host accounts approve <name>
sudo fabricctl host accounts unapprove <name>     # withdraw it: reminded again
```

Both are audited (`LOCAL_ACCOUNT_APPROVE`, `LOCAL_ACCOUNT_UNAPPROVE`) and kept on the host.
