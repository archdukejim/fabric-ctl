## 4.3.6.1 Run Guided in the browser

1. Run `sudo fabricctl setup` and choose **Guided**. If ufw is on, the terminal asks one question first: whether to open the
   site's port until the site stops.
2. The terminal prints the site's URL (one per address of the host), the one-time code and the temporary certificate's
   SHA-256 fingerprint. Open the URL in a browser on a computer that can reach the host.
3. The browser warns about the certificate. Open the certificate's details from the warning or the address bar and compare
   its SHA-256 fingerprint with the terminal's. If they differ, stop: someone may be between you and the host. If they match,
   continue past the warning.
4. Enter the code. A code opens one session; a second browser is refused while the first is around.
5. Answer the questions. Those marked **⚠ Permanent** cannot change after the install. A refused answer comes back with why.
6. Read the plan: what setup will do and every change it makes to the host. **Proceed** is the one yes for all of it.
   **Cancel** changes nothing. To change more before installing, cancel, run setup again and choose Advanced in the terminal.
7. The page follows the install live. You can close it: the work goes on, and the same code reconnects while the site runs.
8. Setup done, the site restarts on a certificate from fabric's new CA. The browser warns once more until you trust that CA;
   the page shows the new fingerprint first, and the terminal prints it too.
9. Follow the finish: trust the root (4.3.6.2), point this computer's DNS at fabric (4.3.6.3), press **Check**.
10. Press **Finish**. The site stops and any port it opened is closed. It also stops one hour after setup ended.

To run Guided in the terminal instead, for a host reached with no browser: `sudo fabricctl setup --terminal`.

## 4.3.6.2 Trust fabric's root certificate

Compare the root's SHA-256 fingerprint on the finish page, which the terminal also printed, with the one at
`http://<host_ip>/certs/` before you install it. Then restart your browser and reload the finish page: no warning proves
the root is trusted, unless you already went past that warning, in which case use **Check**. The commands below, with
`<certs_url>` being `http://<host_ip>/certs/`, are what the finish page shows filled in.

Windows, PowerShell as administrator:

```powershell
Invoke-WebRequest <certs_url>root-ca.cer -OutFile $env:TEMP\root-ca.cer
Import-Certificate -FilePath $env:TEMP\root-ca.cer -CertStoreLocation Cert:\LocalMachine\Root
```

macOS, Terminal:

```bash
curl -sSo /tmp/root-ca.crt <certs_url>root-ca.crt
sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain /tmp/root-ca.crt
```

Ubuntu, a terminal (Firefox and Chrome keep their own stores: `install-all` on the certificates page covers them too):

```bash
sudo wget -nv -O /usr/local/share/ca-certificates/fabric-root-ca.crt <certs_url>root-ca.crt
sudo update-ca-certificates
```

## 4.3.6.3 Point a computer's DNS at fabric

These send names under fabric's domain to fabric's DNS and leave everything else as it is. `<host_ip>` is the host's
address, `<domain>` fabric's domain and `<console_name>` the console's name, `fabric-ctl.<domain>` by default. The finish page
shows them filled in. To use fabric for all of a network's names, set its DHCP's DNS server instead (4.10.1).

Windows, PowerShell as administrator. To undo: `Get-DnsClientNrptRule | Where-Object Namespace -eq ".<domain>" | Remove-DnsClientNrptRule -Force`.

```powershell
Add-DnsClientNrptRule -Namespace ".<domain>" -NameServers "<host_ip>"
Clear-DnsClientCache
Resolve-DnsName <console_name>
```

macOS, Terminal. To undo: `sudo rm /etc/resolver/<domain>`.

```bash
sudo mkdir -p /etc/resolver
echo "nameserver <host_ip>" | sudo tee /etc/resolver/<domain>
sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder
dscacheutil -q host -a name <console_name>
```

Ubuntu, with systemd-resolved, a terminal. To undo: `sudo rm /etc/systemd/resolved.conf.d/fabric.conf`, then restart it.

```bash
sudo mkdir -p /etc/systemd/resolved.conf.d
printf '[Resolve]\nDNS=<host_ip>\nDomains=~<domain>\n' | sudo tee /etc/systemd/resolved.conf.d/fabric.conf
sudo systemctl restart systemd-resolved
resolvectl query <console_name>
```

## 4.3.6.4 Troubleshoot the setup site

| Symptom | Cause | Fix |
|---|---|---|
| The browser cannot reach the URL | A firewall between it and the host, or the host's own | The terminal asks about ufw. Otherwise open the port it printed, or `sudo fabricctl setup --terminal` |
| "all are taken" | Something holds every port from 8443 to 8453 | Free one (the message names what holds 8443), or `--terminal` |
| The fingerprints differ | The page may not be the host's | Stop. Do not enter the code. Check the network, or `--terminal` |
| "That is not the code", then "that code is gone" | Five wrong tries replace it | The terminal has printed the new one |
| "Another browser already holds this setup's session" | A code opens one session | Use that browser. If it has gone, try again after two minutes |
| "this page is out of date" | The session changed, or the site restarted | Open the site's address again |
| "idle for 30 minutes" | Nothing was done on the site before Proceed | Nothing changed. `sudo fabricctl setup` starts again, with a new code |
| The page is cut off after Proceed | A network change, or a lost browser | The work goes on. The terminal keeps showing progress, and its last words give the same steps as the finish. After a lost terminal, `sudo fabricctl setup` follows the run again |
| The page shows "Setup stopped" | A step failed; its message is in the log | Fix what it says. `sudo fabricctl setup` resumes from that step |
| **Check** says the name did not resolve here | This computer's DNS is not fabric's yet | 4.3.6.3, then check again. A browser may keep an old answer: restart it |
| **Check** says the certificate is not trusted | The root is not installed, or the browser keeps its own store | 4.3.6.2, then restart the browser |
| **Check** says the console did not answer | Trust and name are fine; the host's side is not | `sudo fabricctl doctor` |
| The page "stays on its temporary certificate" | fabric's CA gave the site no new certificate | The rest of the finish holds. `sudo fabricctl doctor` looks at the CA |
