## 3.10.1.1 What an install or apply sets up

Nothing is done by hand. At each apply:

- **The schema and the organisation's option set** (1.10.4.24.1): the DC's convergence extends the schema additively
  (attributes `fabricDhcpOptionDef`, `fabricDhcpClass`, class `fabricOptionSet`) and, at the top site only, makes the
  organisation's set `CN=dhcp-options,OU=organisation,…` and the group `fabric-dhcp-org-editors` with its access entry.
  Both steps are idempotent: a second apply finds them and changes nothing. A site's own set is made by its first
  option change.
- **The plan poll** (1.10.4.26): with Kea installed (`install_kea: true`), the apply installs and starts
  `fabric-plan-watch.timer` and its `fabric-plan-watch.service` from `templates/systemd/`; with Kea off, it stops and
  removes them. Its state is `/opt/fabric/config/plan-watch.json` and `plan-dns.json` (0600).

To check after an apply:

```bash
systemctl list-timers fabric-plan-watch.timer
sudo fabricctl ipam option show
```

## 3.10.1.2 The upgrade of the settings' options

At the first apply of 0.8.0 that finds the site's subnets in the plan (after 1.10.4.15's move), the global DHCP
options, option definitions and client classes in `vars.yaml` (`dhcp.options`, `dhcp.option_defs`,
`dhcp.client_classes`) move into the site's option set once (1.10.4.24.4):

- what the site's set already holds keeps the set's value and is listed "not carried";
- the record `/opt/fabric/config/ipam-options-upgrade-<time>.json` (0600) keeps what moved and the settings as they
  were;
- `vars.yaml` keeps `dhcp.interfaces` and the other DHCP settings, without those three lists.

A DC not answering, or options the checks refuse, leave them in `vars.yaml` (still served) and the next apply tries
again; the apply says so. A site whose DC is read-only writes them at its writable partner (`ad_join_server`). Running
the apply again moves nothing.

To restore a setting that should not have moved: read it from the record and set it again with
`sudo fabricctl ipam option set site …` (4.10.2.14).

## 3.10.1.3 Removing it

Turning Kea off (`sudo fabricctl dhcp off`, 4.10.1) removes the poll's units at the apply; uninstall (3.2.4) removes
them with fabric's other units. The option sets stay in the domain with the rest of the plan.
