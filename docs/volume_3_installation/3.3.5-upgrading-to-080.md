# 3.3.5 Upgrading to 0.8.0

Topics:
- 3.3.5.1 Before the upgrade: is the install's id block a site's?
- 3.3.5.2 An install with an older id block: a fresh install

The upgrade itself is 3.3.1.1's: the newer package, then `sudo fabricctl setup`. This subchapter holds the steps that
only the upgrade to 0.8.0 needs.

## 3.3.5.1 Before the upgrade: is the install's id block a site's?

0.8.0 refuses an id block that is not a site's, a million ids from a multiple of a million (decisions 2.1.6.46 and
2.1.6.54, [1.6.3.17](../volume_1_description_and_architecture/1.6.3-samba-directory.md)). An install made with 0.7.0 or
later has one. An install made before 0.7.0 and upgraded since (for example a host installed with 0.6.2 and upgraded to
0.7.0, which kept its numbers) may not. Check before the upgrade:

```bash
sudo grep -E '^posix_id_(start|block):' /opt/fabric/config/vars.yaml
```

- `posix_id_start` a multiple of 1000000 (1000000, 2000000, …) and `posix_id_block: 1000000`, or neither line: the
  block is a site's. Upgrade as 3.3.1.1 says.
- Anything else (for example `posix_id_start: 5001` or `posix_id_block: 100000`): the install is from before 0.7.0.
  0.8.0 does not upgrade it (3.3.5.2).

The same refusal comes from the upgrade itself, before anything changes: setup's or an apply's check of the settings
(`posix_id_start must be a multiple of 1000000 … install it fresh`), or the DC's converge
(`id range … is not a site's block … install it fresh`). Nothing was changed when you see it.

## 3.3.5.2 An install with an older id block: a fresh install

There is no migration of ids before the 1.0 milestone (2.1.1.31): every uid and gid in the domain, on the joined
machines' files and in their caches would have to move. Install the host fresh:

1. Keep a copy of what the install holds, so nothing is lost while the new one is made (3.2.4.1):

   ```bash
   sudo fabricctl uninstall --export /root/fabric-export-before-080
   ```

   The export is a backup only: `fabricctl restore` of it brings the older id block back, which 0.8.0 refuses. Read
   from it what you will set again (the settings in `config/vars.yaml`, the people and devices).
2. Install 0.8.0's package and run setup as a new install ([3.3.1.1](3.3.1-running-setup.md#3311-run-the-installer)):
   `sudo fabricctl setup`. Leave out `posix_id_start` and `posix_id_block` (the defaults are site 1's block), or give
   a site's block.
3. Set again what the old install held: people, devices, DNS records, DHCP subnets (now the address plan,
   [4.10.2](../volume_4_operations/4.10.2-address-manager.md)). Machines joined to the old domain join the new one
   again ([4.6.6](../volume_4_operations/4.6.6-linux-join.md), [4.6.7](../volume_4_operations/4.6.7-windows-join.md)).
4. Once the new install works, move the export offline or delete it: it holds the old CA's keys and secrets in plain
   text.

A site that joined below an install with an older block joins the new install again
([3.9.1](3.9.1-joining.md)).
