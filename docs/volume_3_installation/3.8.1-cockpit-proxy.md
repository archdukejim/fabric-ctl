## 3.8.1.2 Preparing a device's Cockpit by hand

For a device that is not a domain member (a member's join script does this, 1.6.7), on the device, as root:

1. Give Cockpit a certificate from fabric's CA for the device's own name (`<hostname>.<domain>`), for example by
   ACME against fabric's Step-CA, and place the certificate and key in `/etc/cockpit/ws-certs.d/` (Cockpit uses the
   last `.cert`/`.crt` file there by name). nginx refuses a self-signed one (1.8.7.5).
2. Allow the proxied name in `/etc/cockpit/cockpit.conf`:

   ```ini
   [WebService]
   Origins = https://<the proxied name> wss://<the proxied name>
   ProtocolHeader = X-Forwarded-Proto
   ```

3. Restart Cockpit: `systemctl try-restart cockpit`.
4. Allow fabric's host to reach the device's port 9090 in the device's firewall (only fabric's host need reach it).

Then add the device to fabric's list (how is settled when it is built, 1.8.7.11) and open its name.

**After the name is changed on the DNS page** (1.8.7.12), redo step 2 with the new name and step 3 on any device
whose `cockpit.conf` fabric does not write; until then the device refuses sessions at the new name.
