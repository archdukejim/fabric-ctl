## 3.1.5.1 What the lab is for

**Being built by the owner** (2.1.1.63, 2026-10-20); until it is ready, 0.8.0's tests run in the containers.

Decision 2.1.1.63: 0.8.0's domain work is tested on real machines on gaming-23's Hyper-V, beside the containers of the
automated suites (3.1.2): fabric installed fresh and moved from 0.7.1 (3.3.5), a second site joining, Linux members of
both machine types, a Proxmox VE 9 host, and Windows members (the grants' GPOs, RSAT for the Directory Administrators,
the console in a browser). The owner runs the commands that need administrator rights on gaming-23; the agent does
everything inside the VMs over SSH.

| VM | Installer | vCPU / memory / disk | Address | For |
|---|---|---|---|---|
| `g23-vm-ub24-1` | Ubuntu Server 24.04 | 4 / 8 GB / 64 GB | `10.88.0.10` | fabric, the root site (fresh install, the move) |
| `g23-vm-ub26-1` | Ubuntu Server 26.04 | 4 / 8 GB / 64 GB | `10.88.0.11` | fabric, a second site (its join; then a read-only DC) |
| `g23-vm-ub26-2` | Ubuntu Server 26.04 | 2 / 2 GB / 32 GB | `10.88.0.21` | a Linux server member |
| `g23-vm-pve9-1` | Proxmox VE 9.1 (Debian 13) | 2 / 4 GB / 48 GB | `10.88.0.22` | a Proxmox host as a server member |
| `g23-vm-kub26-1` | Kubuntu 26.04 | 2 / 4 GB / 48 GB | `10.88.0.31` | a Linux desktop member |
| `g23-vm-ws25-1` | Windows Server 2025 (evaluation) | 2 / 4 GB / 64 GB | `10.88.0.41` | a Windows server member; RSAT |
| `g23-vm-w11-1` | Windows 11 25H2 | 2 / 4 GB / 64 GB | `10.88.0.42` | a Windows desktop member |

All seven together take 34 GB of gaming-23's 64 GB; a test starts only the VMs it needs. The network is
`10.88.0.0/24` on an internal switch, `fabric-lab`, with gaming-23 at `10.88.0.1` giving the VMs internet through NAT
(for packages and images) and nothing else: the owner's LAN is not on it, so the lab's DNS and, later, its DHCP never
reach the house. Each VM's address is set by hand in its installer.

## 3.1.5.2 Build the switch and the VMs

On gaming-23, in **PowerShell run as administrator**, from the repository's checkout:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\lab\new_hyperv_lab.ps1
```

It makes the switch `fabric-lab`, the host address `10.88.0.1`, the NAT `fabric-lab-nat` and the seven VMs
(generation 2; Linux with the Microsoft UEFI CA secure-boot template; Windows with a virtual TPM), each with its
installer ISO from `D:\os\AMD64-x86` as the first boot device and its disk in `D:\Hyper-V\fabric-lab`. It checks
every ISO first and changes nothing if one is missing. Run again, it keeps what exists and makes only what is
missing. `-Only g23-vm-ub24-1,g23-vm-ub26-2` makes only those; `-IsoDir` and `-VmDir` change the folders.

## 3.1.5.3 Install each VM

Start each VM in Hyper-V Manager and connect to its console. Every VM: the address from 3.1.5.1 with prefix length 24,
gateway `10.88.0.1`, DNS `1.1.1.1` (fabric's DNS replaces it when the machine joins); an administrator account
`labadmin` with a password of your choosing (the agent never needs it).

- **Ubuntu Server (ub24-1, ub26-1, ub26-2):** at the network step choose *Edit IPv4* → *Manual*; at the SSH step tick
  *Install OpenSSH server*; no snaps. Once installed, *Media* → *DVD Drive* → *Eject* and reboot.
- **Kubuntu (kub26-1):** a normal install with `labadmin`; then in Settings → Network set the address by hand, and in
  a terminal `sudo apt install -y openssh-server`.
- **Proxmox VE (pve9-1):** its installer asks the address, gateway and DNS directly; hostname `g23-vm-pve9-1.lab.test`.
  It signs in as `root`; make the `labadmin` account afterwards in its shell: `adduser labadmin && apt install -y sudo
  && usermod -aG sudo labadmin`.
- **Windows Server 2025 (ws25-1):** *Windows Server 2025 Standard Evaluation (Desktop Experience)*; the local
  Administrator's password at the end; then a local administrator `labadmin`. In an elevated PowerShell inside the VM:

  ```powershell
  New-NetIPAddress -InterfaceAlias Ethernet -IPAddress 10.88.0.41 -PrefixLength 24 -DefaultGateway 10.88.0.1
  Set-DnsClientServerAddress -InterfaceAlias Ethernet -ServerAddresses 1.1.1.1
  Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
  Set-Service sshd -StartupType Automatic; Start-Service sshd
  ```

- **Windows 11 (w11-1):** at the network screen, `Shift+F10` and `start ms-cxh:localonly` gives a local account
  `labadmin` (no Microsoft account). Then the same four lines inside it, with `10.88.0.42`.

## 3.1.5.4 Give the agent its way in

The agent signs in with the lab key `g23_lab` (in `%USERPROFILE%\.ssh\` on gaming-23), never with a password. From an
ordinary PowerShell on gaming-23, once per VM (it asks `labadmin`'s password once):

```powershell
$k = Get-Content $env:USERPROFILE\.ssh\g23_lab.pub
$k | ssh labadmin@10.88.0.10 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
ssh -t labadmin@10.88.0.10 "echo 'labadmin ALL=(ALL) NOPASSWD:ALL' | sudo tee /etc/sudoers.d/labadmin && sudo chmod 440 /etc/sudoers.d/labadmin"
```

and the same for `10.88.0.11`, `.21`, `.22` and `.31`. Passwordless sudo is for the lab's own `labadmin` only, so the
agent can install and test without ever typing a password; it is never set on a production or house machine.

For the two Windows VMs, the key goes in OpenSSH's file for administrators, inside each VM in an elevated PowerShell
(paste the contents of `g23_lab.pub` for `<key>`):

```powershell
Set-Content C:\ProgramData\ssh\administrators_authorized_keys '<key>'
icacls C:\ProgramData\ssh\administrators_authorized_keys /inheritance:r /grant Administrators:F /grant SYSTEM:F
```

Then tell the agent the lab is ready; it checks each VM with `ssh -i ~/.ssh/g23_lab labadmin@<address> hostname`.

## 3.1.5.5 Checkpoints

After 3.1.5.4, take one checkpoint per VM named `clean`, so a test can start again from a fresh machine:

```powershell
Get-VM g23-vm-* | Checkpoint-VM -SnapshotName clean
```

and to put a VM back: `Restore-VMCheckpoint -VMName <name> -Name clean -Confirm:$false`. These need administrator
rights, or membership of gaming-23's local **Hyper-V Administrators** group, which lets that account start, stop,
checkpoint and restore VMs without being an administrator. If the owner adds the agent's account to it
(`Add-LocalGroupMember -Group 'Hyper-V Administrators' -Member $env:USERNAME`, then sign out and in), the agent
restores and starts the VMs itself; otherwise it asks the owner for each restore.

## 3.1.5.6 Take the lab down

```powershell
powershell -ExecutionPolicy Bypass -File scripts\lab\remove_hyperv_lab.ps1
```

It lists what it removes (the seven VMs with their disks, the NAT, the switch and its host address), asks once, and
removes only those.
