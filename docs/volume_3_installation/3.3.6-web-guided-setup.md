## 3.3.6.1 Start Guided in the browser

On a new install, from a terminal on the host. The package is installed as in
[3.3.1.1](3.3.1-running-setup.md#3311-run-the-installer); nothing more needs installing, because the site is Python's
standard library, `openssl` and files in the package.

1. Run setup:

   ```bash
   sudo fabricctl setup
   ```

2. At `Guided, Advanced or Quit?`, press Enter for Guided.
3. If ufw is on and would block the site's port, answer the one question the terminal asks. Yes opens that port from this
   LAN until the site stops. No stops setup, with nothing changed, and says to use the terminal (3.3.6.2).
4. Open one of the URLs the terminal prints, and go on at [4.3.6.1](../volume_4_operations/4.3.6-web-guided-setup.md#4361-run-guided-in-the-browser).

The site uses TCP 8443, or the next free port up to 8453, and the terminal says which and what held the others. If all
eleven are taken, setup says what holds 8443 and offers the terminal.

## 3.3.6.2 Run Guided in the terminal instead

For a host with no browser in reach, or when the site is refused or will not start:

```bash
sudo fabricctl setup --terminal
```

Everything else about Guided is the same: the same questions, checks, plan and host changes. Advanced, `--non-interactive`,
`--file`, upgrades and re-runs never start the site.

## 3.3.6.3 Clear what a killed setup left

A setup killed outright (`kill -9`, a power cut) cannot stop its own site. The listener ends with it, and the firewall rule
stays until something removes it.

1. Run setup again. A full run with no live site removes the leftover rule first, by its comment `fabric-setup-site`:

   ```bash
   sudo fabricctl setup
   ```

2. Uninstalling removes it too. To see whether one is there:

   ```bash
   sudo ufw show added | grep fabric-setup-site
   ```

## 3.3.6.4 Build and test the setup site

- **Packaging:** `packaging/deb/assemble-tree.sh` puts `templates/setup-site/` and `static/setup-site/` in
  `/usr/lib/fabricctl/fabric/lib/setup-site/`, kept out of the service templates.
- **The drawings:** `static/setup-site/*.svg` are made by `scripts/docs/draw_setup_site.py`; change them there and commit
  the result.
- **Tests:** [3.1.2.5](3.1.2-automated-tests.md#3125-the-entry-point-inventory) lists the site's entry points. As root, on
  Linux:

  ```bash
  python3 tests/setup/site/site_test.py
  ```

  ```bash
  python3 tests/setup/site/flow_test.py
  ```

  ```bash
  python3 tests/setup/site/guides_test.py
  ```

  ```bash
  python3 tests/setup/site/browser_test.py
  ```

  The first three run in the `consent` suite. `browser_test.py` needs Docker for its real Chromium and runs in the `webui`
  suite. `tests/sandbox/web_guided.sh` is the whole run from the built package, in a sandbox.
