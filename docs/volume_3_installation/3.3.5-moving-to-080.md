# 3.3.5 Moving to 0.8.0

Topics:
- 3.3.5.1 [DELETED] Before the upgrade: is the install's id block a site's?

There is no upgrade into 0.8.0 (decision 2.1.1.60): every install of 0.7.x moves to it by its settings file. From 0.8.0
on, releases upgrade in place again (2.1.1.61).

## 3.3.5.1 Before the upgrade: is the install's id block a site's?

This item has been removed from scope of fabric-ctl as of 0.8.0 / 2026-10-18. See 3.3.5.4 for newest applicable
method: no install is upgraded into 0.8.0, whatever its id block.

## 3.3.5.2 An install with an older id block: a fresh install

This item has been removed from scope of fabric-ctl as of 0.8.0 / 2026-10-18. See 3.3.5.4 for newest applicable
method: every install moves the same way.

## 3.3.5.3 What the move keeps, and what it makes new

| Kept, through the settings file | Made new |
|---|---|
| the domain's names, the DNS zones and records, the TSIG keys' names and rights, the parts chosen and their settings | the CA (a new root every machine must trust; every certificate issued again), the TSIG keys' secrets, OpenBao and its secrets, the AD domain (its people, groups and joined machines) |

Keys of the 0.7.x file that 0.8.0 no longer takes (`dc_name`, `posix_id_start`, `posix_id_block`, `logon_policies`,
the site roles' settings, ...) are listed by setup and ignored. Exporting the keys too, so a move keeps them, is
backlog for 1.0 (2.1.1.60).

## 3.3.5.4 The move, step by step

1. **Copy the settings file off the host,** to the machine you work from:

   ```bash
   scp <user>@<host>:/opt/fabric/config/vars.yaml ./vars-0.7.yaml
   ```

   If your user cannot read it, copy it on the host first with `sudo install -m 0600 -o "$USER"
   /opt/fabric/config/vars.yaml ~/vars-0.7.yaml` and `scp` that one.
2. **Keep a full backup** while the new install is made (3.2.4.1). It holds the old CA's keys and secrets in plain
   text, and is never restored into 0.8.0:

   ```bash
   sudo fabricctl uninstall --export /root/fabric-export-before-080
   ```

3. **Install 0.8.0's package** as a new install ([3.3.1.1](3.3.1-running-setup.md#3311-run-the-installer)), then copy
   the settings file back to the host and run setup with it:

   ```bash
   sudo fabricctl setup --file ~/vars-0.7.yaml
   ```

   Setup lists the keys it ignores, asks for what 0.8.0 adds (the first Directory Administrator, 2.1.6.69), and
   writes the break-glass password to `~/fabric-admin/`: copy it into your own safekeeping, then delete the file.
4. **Check it** with `sudo fabricctl doctor` and the console at `https://fabric-ctl.<domain>/`.
5. **Move the backup offline, or delete it,** once the new install works.

## 3.3.5.5 After the move: machines and clients

- **The new CA:** every machine and browser that trusted the old root takes the new one, from the login kit
  ([3.3.2](3.3.2-after-setup.md)) or `http://<host_ip>/certs/`; services with fabric's certificates get new ones.
- **DNS-01 clients:** each takes its TSIG key's new credentials file from the console (DNS → Zones → TSIG).
- **Joined machines** join the new domain again ([4.6.6](../volume_4_operations/4.6.6-linux-join.md),
  [4.6.7](../volume_4_operations/4.6.7-windows-join.md)).
- **A site joined below the old install** joins the new one again ([3.9.1](3.9.1-joining.md)).
