## 3.9.1.1 Joining an existing fabric (a new site)

On the fabric this site joins (its upstream; design [federation.md](../volume_1_description_and_architecture/1.9.1-sites.md#1911-status)):

```bash
sudo fabricctl federation enable          # once: the endpoint sites join through
sudo fabricctl federation invite branch1  # one-time invitation, good for one hour
```

On the new host, a fresh install:

```bash
sudo fabricctl setup --join            # paste the invitation at the (hidden) prompt
```

Nobody names the site's domain controller (2.1.6.65): the upstream gives it the lowest `dc-NNNN` the organisation's
domain does not have, in the join's answer, and the joining site's DC joins under that name (setup asks nothing; a
vars file that sets `dc_name` is refused). A domain that already has `dc-1999` refuses the join, saying so, and the
invitation stays good ([1.6.5.26](../volume_1_description_and_architecture/1.6.5-samba-dc.md#16526-dcs-numbered-dc-nnnn-each-with-its-own-id-range)).
An upstream older than 0.8.0 names no DC: upgrade it before inviting the site.

The site's name comes from the invitation; its domain defaults to `<site>.<organisation domain>`
(set `domain` in a `--file` to choose another). Its certificate authority is an intermediate signed by
the organisation's root (the key is made on the site and never leaves it), and it shares the
organisation's name (`ldap_base_dn`). Its directory is its own DC until the sites share one AD domain (build
step S8, [1.9.8](../volume_1_description_and_architecture/1.9.8-federation-on-ad.md)).
