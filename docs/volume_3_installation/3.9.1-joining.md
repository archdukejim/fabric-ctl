## 3.9.1.1 Joining an existing fabric (a new site)

On the fabric this site joins (its upstream; design [federation.md](../volume_1_description_and_architecture/1.9.1-sites.md#1911-status)):

```bash
sudo fabricctl federation enable          # once: the endpoint sites join through
sudo fabricctl federation invite branch1  # one-time invitation, good for one hour
```

On the new host, a fresh install:

```bash
sudo fabricctl setup --join            # paste the invitation at the (hidden) prompt
```

The upstream must run fabric 0.8.0 or later: the invitation carries its version, and setup `--join` refuses an
invitation from an older upstream (or one naming no version) at once, before anything is sent or changed. Upgrade the
upstream first, then make a new invitation there.

Nobody names the site's domain controller (2.1.6.65): the upstream names it in the join's answer and the site's DC
joins under that name (setup asks nothing; a vars file that sets `dc_name` is refused). Setup says how many domain
controllers the domain then uses and how many can still be added (for example `2 DCs used, 1997 can be added`). A
domain with the most domain controllers it may have refuses the join, saying so, and the invitation stays good
([1.6.5.26](../volume_1_description_and_architecture/1.6.5-samba-dc.md#16526-dcs-numbered-dc-nnnn-each-with-its-own-id-range)).

The site's name comes from the invitation; its domain defaults to `<site>.<organisation domain>`
(set `domain` in a `--file` to choose another). Its certificate authority is an intermediate signed by
the organisation's root (the key is made on the site and never leaves it), and it shares the
organisation's name (`ldap_base_dn`). Its directory is its own DC until the sites share one AD domain (build
step S8, [1.9.8](../volume_1_description_and_architecture/1.9.8-federation-on-ad.md)).

The joining site makes no first Directory Administrator of its own (the domain has its own) and so no login kit: its
console is signed in to by the domain's Directory Administrators, with their own passwords, as setup's last words say.
