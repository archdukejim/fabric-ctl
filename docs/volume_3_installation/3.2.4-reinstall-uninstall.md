# 3.2.4 Reinstall, uninstall and restore

Topics:
- 3.2.4.1 Reinstall / Uninstall

## 3.2.4.1 Reinstall / Uninstall

```bash
# Uninstall + restore + setup, keeping everything: config, secrets, the CA and certificates, the directory,
# DNS with its TSIG keys, Keycloak (second factors kept) and OpenBao with its vault key. It asks a passphrase
# for the bundle it makes first (12 characters or more, twice), then asks to continue (--yes: don't).
sudo fabricctl reinstall

# The same, at a new address this host already has (manual 1.3.7.7). To move to another VLAN and subnet, the host
# is re-addressed between the uninstall and the restore instead: manual 4.2.4.8
sudo fabricctl reinstall --set host_ip=10.0.5.2 --set lan_cidr=10.0.5.0/24 --set lan_gateway=10.0.5.1

# Remove fabric. It asks first: an encrypted backup bundle of all of fabric (default yes, its passphrase
# asked twice)? remove the fabricctl package too (apt purge)?
sudo fabricctl uninstall

# Unattended: the backup choice must be explicit; the passphrase comes from a root-only file, never an argument
sudo fabricctl uninstall --yes --backup --key-stdin --purge-package < /root/bundle-passphrase
sudo fabricctl uninstall --yes --no-backup

# Bring it back from its bundle (the same host or a new one, package installed): asks the passphrase
sudo fabricctl restore /var/backups/fabric/fabric-<host>-<time>-uninstall.fabric.tar
```

Both make a **cold bundle** first (manual [1.3.7.2](../volume_1_description_and_architecture/1.3.7-backups.md),
1.3.7.4): fabric is stopped and proven stopped, then every section is packed, compressed and encrypted, into one
root-only file in `/var/backups/fabric/` (`…-reinstall.fabric.tar`, `…-uninstall.fabric.tar`). Nothing is written
unencrypted. The bundle stays after the reinstall or uninstall: it is the backup of the install as it was. Keep the
passphrase: without it the bundle cannot be opened.

`fabricctl reinstall` checks the changes asked (`--set`: `host_ip`, `lan_cidr`, `lan_gateway`, `dns_server`; not the
host's name, which 4.2.4.3 changes), that this host has the new address, that the install has no linked sites, and the
passphrase, before anything is stopped. It then makes the bundle, uninstalls (the host's
own computer account stays: the restored directory still holds it), restores the bundle whole with the changes and
runs setup on it with your other options. If the restore stops part way, fabric is removed and the error names the
bundle: `sudo fabricctl restore <bundle>` finishes it.

`fabricctl restore <bundle>` asks the passphrase (`--key-stdin`: from standard input; `--key-file PATH`: a schedule's
private key in a root-only file), checks the bundle whole and of a fabric no newer than the package, puts every
section back in place (owners, modes, ACLs kept) and runs setup on it unattended: the same CA, directory, Keycloak, DNS
with its TSIG keys and OpenBao with its vault key. It refuses while fabric is installed (`--section NAME` restores
one section on a running install instead: 1.3.7.8). `fabricctl restore <folder>` still restores an export folder made
by 0.10.0's `fabricctl uninstall --export`.

`fabricctl uninstall` asks every question before anything is touched, after a list of what happens to each host
change fabric made (removed, undone or kept): a backup bundle first (default yes)? its passphrase? remove the package
too (default no)? then type `yes`. With `--yes` the backup choice must be given (`--backup` or `--no-backup`).
0.10.0's `--export DIR` is taken as `--backup`, saying so (the bundle goes to `/var/backups/fabric/`, not DIR), and
`--no-export` as `--no-backup`. If the bundle cannot be made (too little room, OpenBao not answering), nothing is
removed; if fabric was stopped for the copy, `sudo fabricctl start` starts it again.

A setup still running (`fabric-setup.service`, 3.3.1.1.6) is stopped first,
before anything is removed. It removes every service and `fabric.target` (and systemd's record of each fabric
timer's last run, so a later install's daily renewal does not fire before its CA runs; setup also drops a stamp an
older release left when it installs that timer: 2.3.1.32 finding 17; every fabric unit's failure is cleared, so
none is left "not-found failed": finding 18), the
containers, the
`fabric_net` network, fabric's locally built images, the `/opt/<service>`
folders (and TSIG credential folders), the vault key and unlock-method files,
the USB kill-switch rule, the service accounts and a checkout-era
`/usr/local/bin/fabricctl`. It undoes the host changes: fabric's ufw rules,
`DOCKER-USER` rules and `fabric-firewall.service` (ufw switched off again if it
was off before fabric), the resolver (stub listener and `/etc/resolv.conf`
back), chrony's files as they were, the CA in the host trust store, and the host's `local-admin` that fabric made
(the account and its home, its SSH drop-in; refused by `userdel` while it is signed in, which uninstall says:
[1.7.1.4.1](../volume_1_description_and_architecture/1.7.1-openbao.md#1714-the-fabric-hosts-local-admin-080)).
Docker's daemon settings stay (putting them back restarts Docker: run
`sudo fabricctl setup --undo runtime` first if you want that), as do apt
packages. Docker, downloaded images and other containers are not touched.

| Command | fabric install | Package | Backup bundle |
|---|---|---|---|
| `sudo fabricctl uninstall` | removed | removed if you say so | if you want one (default yes), with your passphrase |
| `sudo fabricctl reinstall` | removed and restored | kept | always, with your passphrase |
| `sudo apt remove fabricctl` | **kept, still running** | removed | — |
| `sudo apt purge fabricctl` | removed only with a backup schedule's public key set; **kept, still running** otherwise | removed | sealed to the schedule's public key (apt cannot ask a passphrase) |

The bundle holds the config, fabric's secrets, the whole CA, the directory, Keycloak's database, every certificate and
OpenBao's data with its vault key, each section encrypted. Whoever has the bundle and its passphrase (or the schedule's
private key) has your CA and your vault: keep the passphrase apart from the bundle, and a copy of the bundle off the
host.
