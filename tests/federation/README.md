# tests/federation

| File | What |
|---|---|
| `run.py` | Invitations (made, hashed, listed, withdrawn, expired), the federation endpoint's routes and refusals, a site joining an upstream end to end with the real Step-CA image (pinned root, TLS to the endpoint's name, site CA signed by the root, records on both sides, single use, idempotent re-run), the endpoint socket's uid check, the DNS link key on both sides and removing a site; runs `dns.py`, `nested.py`, `address_plan.py`, `directory_links.py` and `replication.sh` at the end |
| `dns.py` | DNS between sites with two real BIND servers configured from fabric's templates: delegation with glue, secondary copies both ways, transfers refused without the link's key or with a wrong one, a change reaching the other site by NOTIFY |
| `nested.py` | Nesting and re-parenting with three installs side by side: a root of path length 2 invites `lab` with `--nest 1`, lab invites `lab2` nested under it, lab2's CA and devices chain to the root through lab, lab2 moves under the root; `lab3` joins through the relay node `edge` (the root signs, edge only forwards), then drops the relay; nesting deeper than a CA allows, a path-length-0 site inviting and an unknown relay are refused |
| `address_plan.py` | The address plan's rules: what a site reports, which overlaps are conflicts (a reason allows one), a joining site with an overlapping network refused (also with the directory away), `fabric_subnet` refused for a subnet |
| `directory_links.py` | The replication plan for every shape a site can take: standalone (nothing), the root with a site, a leaf site, a hub, a link without its secret |
| `replication.sh` | Directory replication (M5) with two real 389-DS set up by `configure_directory_links`: the organisation reaches the site read-only and writes there are referred to the root, the site's part reaches the root, the link's secret on no command line, the site answering with the root down and both catching up, a removed site's agreement going (the address plan lives in AD since S4: tests/samba/dc.py) |
| `role.py` | One install's federation side for `nested.py` (invite, signing capacity, the endpoint over TLS), imported from that install's own tree |
| `roles_test.py` | Layered roles and sibling isolation without containers (2.1.9.21, 2.1.9.22): the site groups Keycloak maps (its own only), granting from the CLI and the agent route, `fabricctl federation roles`, the address plan a site shows (Federation tab, `federation networks`, `ipam find`; an overlap with a hidden site counted), the Roles card and the People note, and the console's role and Unlock posts (the agent stubbed). In `run-all.sh`'s `consent` line |
| `dc_type_test.py` | Container-free (`consent` in run-all): a site's DC type change (2.1.9.23; asked from the console too, revised 2026-10-14: the agent's route for `federation:admin`, the token shown once, its refusals): the request from above and its refusals, the change token at the site above, the site's plan and steps resumed from the record, the command and its questions |
| `rodc_lost_test.py` | Container-free (`consent` in run-all): a lost read-only DC (2.1.6.58; `federation:admin` since 2026-10-14): exactly the revealed accounts listed and only those reset, the refusals, the record and a second run, the agent's and console's routes, the command, the page |
