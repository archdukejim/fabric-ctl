# tests/ipam

The `ipam` suite (manual 1.10.4.3, 1.10.4.41): the address manager's model, with no container.

| File | What |
|---|---|
| `run.py` | The rules (VLANs, subnets and overlaps, ranges, one claim per address, only reservations in a dhcp range), the suggestions, the site's number, several subnets on one VLAN, adding and changing a subnet, the small parts (0.7 pools, the option list, `ScanBusy`), one site's plan out of read_plan's answer on 0.8.0's directory, the address table, find, export and show, one change made the way every command makes it (the grant first, the writable DC, nothing written on a refusal), `fabricctl ipam`'s refusals that need no domain; area 5: a plan rendered for Kea and checked by fabric, a name set by hand winning over DHCP's (2.1.10.20) |
| `options.py` | The DHCP options in the plan (decisions 2.1.10.23 to 2.1.10.25, manual 1.10.4.24 to 1.10.4.26): the option sets' checks and merge, where a change works (0.8's `org` read as `domain`), the netboot presets' checks and Kea classes, the provenance of each option, one option change made the way every option command makes it (the grant's networks options right first, at `all` for the domain's set), and `fabricctl ipam option`, `class` and `netboot`'s refusals that need no domain; area 5: Kea rendered from the option sets and presets (to JSON), the plan poll's states with its steps stubbed, the DNS digest kept only once BIND took it, and `fabricctl ipam watch` |
| `aliases.py` | The old DHCP commands once the plan holds a site's subnets (manual 1.10.4.21, 1.10.4.37): when it does, `fabricctl dhcp add-subnet`, `set-subnet`, `remove-subnet`, `reserve` and `unreserve` routed to their `ipam` functions, their refusals, and the commands that edited the settings refused with nothing saved |
| `upgrade.py` | The upgrade's move into the plan (1.10.4.15, 1.10.4.37): a site's subnets as the plan's changes, the move with the domain stood in for (the DC down, a read-only DC moved through its writable DC, the record, vars.yaml losing its subnets, a second run moving nothing), and the settings' options into the site's set; area 5: nothing a running site serves changes when the plan renders what the settings held, and between applies the plan's copy feeding the firewall, the Kea tab and `dhcp on` |
| `sync.py` | Sync now with no container (2.1.10.29, manual 1.10.4.28): the refusals (an apply running, no Kea, not upgraded) changing nothing, the poll forced under the lock it holds, BIND's records only when DNS waits, a failure said with what was done and audited, `fabricctl ipam sync`; the agent's route and the Networks tab's card come with areas 7 and 9 |
| `networks.py` | The Networks tab's model and its agent routes (1.10.4.21, 1.10.4.35): a subnet's map, the options and their sources, a site's view, `GET /v1/networks` (any site, the kept copy, another site refused with the DC down), the export, each `POST /v1/networks` route accepted and refused, the apply after a change |
| `pending_networks.py` | The address manager's held changes (1.10.4.40.2, .3): the page each route is held on, its sentence, its thing and key, the grant's networks right checked when held and again at Apply, a held change run without its own apply, and the page's finish applying this site's plan once; each accepted and refused |
| `agent_routes.py` | The agent's other address-manager routes (1.10.4.35): the options page's reads and changes (the domain's set as `scope` domain), Sync now and its grant check, the scans' routes, each accepted and refused |
| `locations_test.py` | Locations inside a site (2.1.10.49, 1.10.4.46), with the domain stood in for: two VLAN 10s at one site, a VLAN named `<id>@<location>`, the rules per location, the subnet names, add, move and remove, where it shows (show, the address table's column, Kea's access, the console's view), the agent's VLAN names and `vlan set --to-location`; each both ways |
| `scan.py` | The scan and ping-check with no container (1.10.4.22, 1.10.4.36): the subnet chosen in this site's plan and the refusals, the caller's `scan` checked before anything is probed, one at a time and once a minute, what answered classified and audited, the probe's fixed argument lists, the text, the offer to record each find (a find with no MAC: its MAC typed or a static address, 2.1.10.50), a subnet beyond a router said, `fabricctl ipam scan`, `dhcp.ping_check` and the Kea template's hook, Kea's image's `fping` |
| `scan_requests.py` | Scans at another site with no container (2.1.10.38): a request's checks and refusals, the serving site's answers (not made by a fabric DC's agent, a person without `scan` there, root at a host, expired, removed, one per run, busy, refused), the plan poll answering them and failing loudly, `fabricctl ipam scan --site` and `scan-requests` |
