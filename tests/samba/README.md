# tests/samba

The `samba` suite (manual 1.6.5.13): the Windows domain controller.

| File | What |
|---|---|
| `run.py` | Settings (2.1.6.11, 2.1.6.13), the Administrator's password, the rendered container's hardening, nginx giving up 389/636, the unit |
| `dc.py` | Real containers: a DC from fabric's image run as rendered, deployed and converged by fabric's code (twice: idempotent), the policy and GPOs in place; the address plan (each site's networks converged into AD, read across two sites, an overlap found, a removed network leaving); BIND (fabric's image, sharing the DC's address as on a host) answering the AD zone through DLZ and fabric's zone unchanged, the DC's signed updates accepted; an RODC joining with fabric's image (NTLM forwarded for accounts it does not cache; with the writable DC down, cached people only, no writes); refusals: unsigned updates in either zone, a site admin in another site or its service accounts, a short or wrong password |
| `devices.py` | Devices and device roles on a real DC through fabric's own functions, as the site's agent account: the default roles made once in the organisation's OU, validation and its refusals, effective permissions and VLAN, role membership, certificate links, the audit log |
| `linux_join.py` | Ubuntu 24.04 and 26.04 joining a real DC with fabric's `join-linux.sh` as rendered: a wrong root-CA fingerprint refused (nothing changed), a join with a site admin's password and one with a one-time join password, fabric's ids, a PAM logon and a Kerberos ticket, sudo for a site admin and not a person, a person of another site refused by the log-on GPO, cached logons with the DC stopped; then a log-on policy on OU=machines (1.6.11.4) letting in a person of its group and refusing one outside it; a sudo rule on a host group (1.6.11.7) applying on its member machine and not on another; SSH certificates (1.6.11.9.4; 0.9, not run yet): the user CA fetched over HTTPS from the host's own name and trusted while published, a certificate signing in its principal and no one else, kept while unreachable, removed when withdrawn or taken out |
| `logon.py` | Who may sign in per OU (1.6.11.4) on a real DC, through `fabricctl domain logon`, the agent's routes and the web console's form: the legacy GPO while the setting is null, the first edit keeping today's rights as the site OU's, one GPO per OU linked to it with its console and remote groups plus break-glass and local Administrators, the legacy GPO deleted with its SYSVOL folder, a missing OU reported and skipped, a clear removing its GPO; refusals (unknown group, bad OU, nobody on OU=machines, a clear leaving the machines without a policy) |
| `hostgroups.py` | Host groups and sudo rules (1.6.11.7) on a real DC, through `fabricctl machines` and `fabricctl sudo`, the agent's routes and the web console's forms: host groups with their machines, sudo rules as `sudoRole` objects whose hosts follow their host group (and at convergence), fabric's, the default and an admin's own rule listed; refusals (ALL commands to everyone, unknown people, groups, machines and host groups, bad names, removing the default or an admin's rule, deleting a host group a rule names); who is a fabric admin (directly or through a nested group; 0.9, not run yet) |
| `gpo.py` | The ADMX editor (`fabricctl gpo`) on a real DC with Samba's own template and fabric's starter: templates loaded, policies listed, text, boolean and list policies set as Windows' editor writes them, replaced, disabled and cleared; the admin GPO linked with its version bumped; refusals |
| `site_join.py` | Sites joining the root's domain: the root prepares each (OU, groups, accounts, id block, an expiring join account), a writable and a read-only site DC join with fabric's deploy and compose file into their AD sites, replication both ways over the site link, the site's agent at its own DC, the join account deleted, writes refused at the RODC |
| `ipam.py` | The address manager's plan on a real DC (1.10.4.13-16): the schema, a 0.7 site's subnets moved once (recorded, nothing served changed, idempotent, convergence leaving the plan alone), the plan at an apply and its kept copy with the DC away, every `fabricctl ipam` command and its refusals as the site's agent, a parent writing a nested site's plan and the nested site refused its parent's; the DHCP options in the plan (2.1.10.23, 2.1.10.25): the organisation's option set made by the top's convergence, options, definitions and classes at each scope, netboot presets kept beside a subnet's options, another site refused the organisation's options until the top adds it to `fabric-dhcp-org-editors`, a read-only DC's site writing at its writable partner, the settings' options moved once |
| `ipam_two_site.py` | An edit at the top reaching the house (2.1.10.11): a VLAN and a reservation written into a joined site's plan on the root's DC replicate, and the site's USN poll renders them into its Kea within 30 s of its DC holding them; a second claim refused at the top reaches nothing. The house's poll is fabric's own `poll_plan` (its read and render real; Kea's restart and the host firewall left out); in `run-all.sh`'s `samba` line |
| `start_bind.py` | BIND beside a test DC, answering the AD zone through DLZ (for suites with more than one DC) |
| `start_dc.py` | A converged DC for any suite that needs AD (tests/keycloak), and its parts (dc_tls, run_dc): fabric's image, hardening, deploy and convergence, a test PKI |
