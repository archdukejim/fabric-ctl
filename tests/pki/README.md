# tests/pki

| File | What |
|---|---|
| `run.py` | Manual PKI (sign a CSR, generate key + cert, inspect, convert, ledger) and zone TSIG keys against a throwaway CA made with the real Step-CA image, including what must be refused; runs `site_ca.py`, `renewal.py`, `revocation.py`, `acme.py`, `landing.py`, `enrol.py` and `scep.py` at the end; device enrolment through the agent (1.5.3) |
| `enrol.py` | Device enrolment without containers (1.5.3, 2.1.5.12): the one-time SCEP challenge (single use, a retry of its transaction, reuse, expiry, another name, withdrawn: refused; only its hash kept), the webhooks only Step-CA's own certificate may call, the notification recorded as the person and linked to the device, the Apple profile's payloads, the PKCS#12 (opens with its password, refused with a wrong one; AES-256, or 3DES for old Android), the list, revoking, withdrawing, the settings' refusals. Written for 0.9, not run yet |
| `scep.py` | Step-CA's SCEP provisioner against the real Step-CA image (1.5.3.3): the per-install RSA decrypter (made once, its key encrypted), ca.json converged (provisioner, webhooks, :9080, 0600), Step-CA answering GetCACaps and GetCACert; none of it without the web console. Written for 0.9, not run yet |
| `site_ca.py` | Federation site CAs: a site's key and request, signing with the root key (own or brought-in), checking and staging the answer, a leaf from the site CA, Step-CA serving with the encrypted site key; the refusals (wrong name, extra names, weak key, byoc without its root key, wrong password, wrong root, another site's key) |
| `renewal.py` | Certificate renewal without containers (2.1.5.4–2.1.5.7): when a certificate is due (age, lifetime, CA, names), the lifetime settings and their refusals, the reload table, the run's record, `fabricctl certs`' flags, the warnings for status, doctor and the web console, the CA's lifetime (the Advanced question; a change refused on an existing CA) |
| `revocation.py` | Revocation without containers (2.1.5.10): revoking by name and serial, the intermediate's and the root's CRLs (openssl verify refuses the revoked, accepts the rest), what nginx and FreeRADIUS are given, the issued list's state, `fabricctl certs revoke` and `issued`, and the refusals (reason, unknown or ambiguous name, already revoked, a root-signed site CA without the root key) |
| `acme.py` | ACME for LAN machines against the real Step-CA image (2.1.5.8): fabric's converged ca.json and ACME template; a machine gets a 47-day certificate over http-01 naming the CRL; refused: a name outside the domain (even when its challenge passes), an address, a name it does not answer for; `fabricctl acme` and its refusals |
| `landing.py` | The landing page's certificate follows the zone (2.1.4.8) against the real Step-CA image run as setup runs it (a container named `step-ca`): setup issues it for the host's own name, `<domain>` and the aliases of the host; an apply after a rename issues it again at once without the old name and does not revoke the one it replaced (it expires: not in the revocation record or the CRL; 2.1.4.8 revised); refused: nothing issued while the names are current or before the first certificate, a record pointing elsewhere or one of fabric's own names never on it, an apply whose certificate cannot be issued failing loudly with the certificate unchanged |
